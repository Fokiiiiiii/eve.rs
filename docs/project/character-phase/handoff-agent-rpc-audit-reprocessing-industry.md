# RPC audit handoff: corporation members, reprocessing, industry jobs

## Verified findings and changes

- **Corporate member lookup:** the 500 limit is now a query batch size, not an RPC cap. Both `CorporationStore.MembersByIdsAsync` (`dotnet/src/Eve.Corporations/CorporationStore.cs:437-458`) and `PgCharacterStore.ForCorporationByIdsAsync` (`dotnet/src/Eve.Characters/Characters.cs:121-134`) query in chunks of 500. The registered packet regression sends 501 IDs and verifies the final member row in `dotnet/tests/Eve.Host.Tests/CorporationBulkMembersHostWireTests.cs:17-79`. Retail callers send the entire uncached list in one call (`eve/client/script/ui/services/corporation/bco_members.py:31-42`); role management supplies the full sorted member list and reads each row's `characterID` / `baseID` (`eve/client/script/ui/shared/neocom/corporation/corp_ui_member_view_role_mgt.py:142-177`). EveJS 261028.1 maps every supplied ID without an input cap (`server/src/services/corporation/corpRegistryRuntime.js:2784-2794`).

- **Corporation office reprocessing:** output to a corporation is accepted only for flags 115–121, a member with division Query access or Factory Manager, and that corporation's active office at the bound station. The authorization transaction locks the character, corporation, and office; lock order follows role updates, which lock characters before the corporation (`dotnet/src/Eve.Corporations/CorporationStore.Membership.cs:20-34`, `dotnet/src/Eve.Corporations/CorporationStore.Roles.cs:78-105`). Yields use the corporation as owner and are created in the reprocessing transaction (`dotnet/src/Eve.Services.Station/ReprocessingService.cs:169-218,256-272`). The Host regression sends a registered packet for success, verifies corporation-owned yields, and checks invalid-office and member-role rejections leave inputs intact (`dotnet/tests/Eve.Host.Tests/ReprocessingHostTests.cs:128-204`). The client offers office divisions and sends `session.corpid` for those flags (`reprocessing/ui/reprocessingWnd.py:344-368`, `reprocessing/ui/itemReprocessor.py:18-46`); the controller passes returned output types to the results panel (`reprocessing/ui/reprocessingWnd.py:149-184`). EveJS 261028.1 performs the equivalent office, Query-role, and corporation-owner checks (`server/src/services/reprocessing/reprocessingRuntime.js:949-1048`, `server/src/services/reprocessing/industryAccess.js:83-96`).

- **Reprocess result with multiple source locations:** there is no server-only reply that can fix this client flow. The client groups selected items by `item.locationID`, issues one synchronous RPC per group, and extends each two-value RPC result into one shared list (`reprocessing/ui/itemReprocessor.py:18-46`); the controller then unpacks exactly two values (`reprocessing/ui/controller.py:77-81`). One group yields two entries; two groups yield four; zero groups (or no groups that survive item locking) yields an empty list without an RPC. The UI disables the action when there are no reprocessable outputs (`reprocessing/ui/outputItemAdder.py:126-133`, `reprocessing/ui/reprocessingWnd.py:116-128`). A server response has no way to know a later group is coming, and cannot repair the no-call case. EveJS 261028.1 likewise returns one two-value result per RPC (`server/src/services/station/reprocessingService.js:673-764`); it does not aggregate across client RPCs. No reply-shape change was made because it would either drop groups or fabricate results. Fixing this requires changing the client aggregation.

- **Industry Location wire objects:** `InstallJob` reads `PyDict`, `PyObject.Args`, and `PyObjectEx.Dict` in `WireField` (`dotnet/src/Eve.Services.Core/IndustryJobsService.cs:371-384`); location parsing reads the client-consumed `itemID` and `flagID` from nested objects (`IndustryJobsService.cs:325-340`). Retail `InstallJob` sends `job.dump()`, whose payload contains the `Location` instances (`eve/client/script/industry/industrySvc.py:139-146`, `industry/job.py:624-640`); `Location` defines the fields via `industry.Base` (`industry/job.py:684-694`, `industry/util.py:86-100`). Both industry submission UI paths call `industrySvc.InstallJob` (`eve/client/script/ui/shared/industry/submitButton.py:219-222`, `eve/client/script/ui/shared/industry/blueprintEntry.py:305-307`); the return value is ignored. The registered Host test covers `PyObjectEx`, `PyObject`, and dictionary forms (`dotnet/tests/Eve.Host.Tests/IndustryJobsHostWireTests.cs:151-183`). EveJS 261028.1 forwards the install request to its industry operation (`server/src/services/industry/industryManagerService.js:91-95`).
