# Travel deep fix: enforce session change cooldown on location changes

## Decision and client evidence

The whole V24.01 client search found three direct `CmdStargateJump` callsites: `eve-logic/eve/client/script/ui/services/stargate/client/gateJumpSvc.py:98-127`, `eve-logic/eve/client/script/parklife/autopilot.py:343-363`, and `eve-logic/eve/devtools/script/insider.py:630`. GateJumpSvc and autopilot wrap the RPC in `PerformSessionChange` at `gateJumpSvc.py:123` and `autopilot.py:357-360`. The shared client guard raises localized `PerformSessionChangeInProgress` in `eve-logic/carbon/common/script/sys/sessions.py:388-397` and checks the active timer at :418-500. GateJumpSvc consumes the resulting solar-system session change at `gateJumpSvc.py:51-54`; `eve-logic/eve/client/script/parklife/gameui.py:430-472` applies station/space session transitions.

For structure docking, `eve-logic/eve/client/script/ui/services/structure/structureDocking.py:26-53` wraps undock in `PerformSessionChange`. Docking uses `NavigateSystemTo(structureID, 2500, RequestDocking)` and then invokes `structureDocking.Dock` at :62-81; `eve-logic/eve/client/script/ui/services/menusvc.py:2981-2989` routes the menu action there. Thus normal client calls wait for the session timer, while the server must also reject direct RPC calls that bypass the UI guard.

The CCP session-change article specifies a 10-second timer started by docking, undocking, gate/wormhole/system jumps and says it blocks docking and gate jumps: [Session Change](https://support.eveonline.com/hc/en-us/articles/205294121-Session-Change). EVE University lists the same 10-second timer and its blocked actions ([Timers](https://wiki.eveuniversity.org/GCC)); the 2,500m gate interaction range is separately listed at [Stargates](https://wiki.eveuniversity.org/Stargates).

EveJS 261028.1 routes the gate call from `server/src/services/ship/beyonceService.js:4283-4324` to `server/src/space/transitions.js:3687-3927`. That server validates the gate, route, ship, criminal/weapon timers and distance but does not enforce the session-change timer. The V24 client and published mechanics support enforcing the timer server-side.

## eve.rs change and resulting behavior

Host registration is `dotnet/src/Eve.Host/Rpc/AgentRpc.cs:123`; the bound `CmdStargateJump` endpoint is `dotnet/src/Eve.Services.Space/BeyonceService.cs:716-723`. Docking uses `SpaceSessions.DockAsync` in `dotnet/src/Eve.Services.Space/SpaceSessions.Movement.cs:18-54`. Both go through shared `MovementPolicyAsync`; `SpaceSessions.Movement.cs:303` now supplies the actual active session timer from `_transitions.SessionChangeActive(...)`, instead of excluding Dock and GateJump. The shared policy also protects wormhole and cyno jumps through `SpaceWormholes.cs:131` and `SpaceSessions.CynoJump.cs:70,196`. Refusals occur before sending a sim command, using existing movement error mappings.

Database-backed regressions in `dotnet/tests/Eve.Services.Space.Tests/SpaceServiceTests.cs:2374-2408` undock and immediately attempt structure docking and gate jumping. They assert a refusal and no additional sim message. Both fail if the old Dock/GateJump exemptions are restored, and pass with the fix. Related dock, gate, cyno, wormhole and tether tests use a test-local timer fixture that completes only the normal 10-second session timer; tests explicitly injecting active timers retain their intended coverage. The shared default in `Rig.cs:102-106,270` now models that elapsed timer for movement test scenarios.

The live structure flow in `tools/headless-client/tests/test_structures.py:181-215,299-321` waits out undock's 10 seconds, retries `DockingApproach` while the ship reaches the 2,500m docking range, and the shared `_docked_pilot` helper allows one additional 11-second wait if the server still reports `DockingRequestDenied`. It then checks `OnDockingFinished` and undocks. This follows the client's navigation call instead of treating an out-of-range request as immediate docking.

## Docking, undocking, warp and gate audit

### Undocking and contraband

Station undock is initiated through `PerformSessionChange('undock', shipsvc.Undock...)` in `eve/client/script/ui/station/base.py:487-508`; structure undock uses the same session flow in `eve/client/script/ui/services/structure/structureDocking.py:25-45`. Both callers retry with `ignoreContraband` after the `ShipContrabandWarningUndock` confirmation. In eve.rs the bound `ShipService.Undock` is registered in `dotnet/src/Eve.Host/Rpc/AgentRpc.cs:119-123`, then `SpaceSessions.UndockAsync` runs the transition in `dotnet/src/Eve.Services.Space/SpaceSessions.Ships.cs:28-80`. The Host supplies the persisted customs penalty provider at `dotnet/src/Eve.Services.Space/SpaceComposition.cs:285-286`.

EveJS 261028.1 validates the strategic cruiser subsystem fit before `undockSession` (`server/src/services/ship/shipService.js:2101-2143`); its transition code defers `inspectContrabandForTransition` until an undock can proceed (`server/src/space/transitions.js:858-883,2249-2491`). eve.rs previously applied the confirmed contraband penalty before checking that a Tengu had its required subsystems. The user could therefore lose ISK or goods while the ship remained docked. Penalty application now follows fit validation in `SpaceSessions.Ships.cs:74-80`. `SpaceServiceTests.An_incomplete_tengu_does_not_pay_an_undock_contraband_penalty` proves that the confirmed warning path returns the expected error, leaves the ship docked, emits no `SimEnter`, and does not call the penalty provider (`dotnet/tests/Eve.Services.Space.Tests/SpaceServiceTests.cs:1025-1044`). The regression failed before the fix with one penalty call and passed after it.

### Docking range

Station and structure dock actions enter through separate client menu handlers (`eve/client/script/ui/services/menusvc.py:2980-2990`, `eve/client/script/ui/services/structure/movementFunctions.py:346-387`). The Host passes dock requests from `SpaceSessions.DockAsync` into the simulator (`dotnet/src/Eve.Services.Space/SpaceSessions.Movement.cs:18-54`). The simulator measures surface distance and applies the same kind-specific threshold both to an immediate dock and to the movement approach (`crates/eve-space/src/scene/docking.rs:142-215`, `crates/eve-space/src/scene/session.rs:729-734`, `crates/eve-space/src/scene/mod.rs:83-90`).

EVE University documents a 500 m docking interaction range for NPC stations ([Warp mechanics](https://wiki.eveuniversity.org/Warp_mechanics), [Navigation 101](https://wiki.eveuniversity.org/User%3AJalxan/Navigation_101)). EveJS 261028.1 uses 2,500 m in `server/src/space/runtime/stationDockingGeometry.js:59,248`. The simulator accepted NPC station docks out to 2,500 m, which was too permissive. It now uses 500 m for NPC stations while retaining EveJS's 2,500 m range for Upwell structures, for which the cited station-specific mechanic does not establish a different range. Tests cover the station threshold and preservation of structure range in `crates/eve-space/src/scene/tests.rs` (docking range tests). The focused test failed before the fix at 500.5 m and passes with the correction. This intentional EveJS divergence is recorded in `docs/reference/compat/DEVIATIONS.md`.

### Warp and stargate jumps

Warp callers include `michelle.CmdWarpToStuff` at `eve/client/script/remote/michelle.py:732-740` and menu, bookmark and autopilot actions. Host dispatch uses `SpaceSessions.WarpAsync` / `WarpCommandAsync` (`dotnet/src/Eve.Services.Space/SpaceSessions.Movement.cs:76,204-273`); the simulator enforces the minimum warp distance (`crates/eve-space/src/scene/warping.rs:48,98-100`, `crates/eve-space/src/scene/warp.rs:13`). EVE University documents the 150 km minimum ([Warp](https://wiki.eveuniversity.org/Warp)). The audited formula and client-visible response path matched; no warp defect was found in this pass.

The whole-tree client search found `CmdWarpToStuff` callers in `menusvc.py:1427,2737-2757`, `menuSvcExtras/movementFunctions.py:418-488`, `addressBookEntries.py:155`, `neocom/journal.py:452`, `infoPanels/listSurroundingsBtn.py:381`, `escalationContentPiece.py:74`, `transmissionMgr.py:142`, `objectives/client/objective_task/dungeon.py:341,369`, and `jobboard/client/features/dungeons/escalation_sites/job.py:57`; autopilot uses `CmdWarpToStuffAutopilot` at `parklife/autopilot.py:464`. `michelle.py:732-740` updates fleet formation settings, forwards subject, ID and kwargs to the remote ballpark, and returns no RPC result to its callers. Warp effect ordering is client-local in `eve/client/script/environment/effects/Warp.py:444-522` (`OnWarpStarted`, `OnWarpActive`, `OnWarpStarted2`, `OnWarpDecelerate`, `OnWarpArrived`, then `OnWarpFinished`); consumers include `tacticalNavigation/tacticalNavigationService.py:476-481`, `carbon/client/script/environment/audioService.py:714-718`, and dungeon objective callbacks at `objectives/client/objective_task/dungeon.py:85-95,201-219,252-265`. This response path is driven by Destiny movement state and its effect notifications, not a value returned by the warp RPC.

Gate callers, session-change handling and refusal error are traced above. The client invokes `CmdStargateJump` through `PerformSessionChange`, surfaces the in-progress session-change error, and follows the system-change notification rather than relying on an RPC payload (`stargate/client/gateJumpSvc.py:98-127,51-54`; `carbon/common/script/sys/sessions.py:388-397,418-500`). Eve.rs checks interaction range in the simulator (`crates/eve-space/src/scene/jump.rs:30,85-86`; `crates/eve-space/src/scene/gate.rs:13`); EVE University documents 2,500 m ([Stargates](https://wiki.eveuniversity.org/Stargates)). The prior cooldown fix is covered by the database-backed docking and jump regressions above.
