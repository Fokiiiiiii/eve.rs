## EveJS 261108.1 behavior comparison

- `Handle_FitShips` uses the same keyword/positional arguments, requires the current docked location, splits one packaged hull at a time, invokes the existing fitting path, and returns `[failedToLoad, failedShipID]` on failure (`server/src/services/ship/shipService.js:1795-1965`). `Handle_LaunchFromContainer` delegates to maintenance-container launch (`:1594-1611`).
- `Handle_Scoop` dispatches ordinary scoopable containers, Mobile Tractor Units and Mobile Depots; the separate handlers cover Fleet Hangar and Mobile Depot hold (`shipService.js:1376-1414`). Mobile Depot recovery ejects contents into a Cargo Container at the depot's position before notifying the depot move (`mobileDepotRuntime.js:808-930,1716-1810`).
- `Handle_BoardStoredShip` swaps the active hull from an accessible maintenance container and returns the activation payload (`shipService.js:1985-2023`). `Handle_SetShipPassword` refreshes the ship harmonic after accepting the password (`:2232-2250`). Tower password storage uses SHA-256 of the UTF-8 password followed by Node's default scrypt output (`starbase/starbaseAccessRuntime.js:196-220`).
- A full-tree search found no `Handle_ScoopToInfrastructureHold`. The V24 wrapper and checker do call that method, so eve.rs follows the client's SDE hold eligibility and capacity rules. The client sends fighters through its fighter service rather than this RPC. The current eve.rs `Scoop` implementation does not yet support Mobile Tractor Unit retrieval; the server has no matching persisted deployable runtime to connect.

## eve.rs implementation

- Registered `FitShips`, `ScoopToFleetHangar`, `ScoopToInfrastructureHold`, `ScoopToMobileDepotHold`, `SetShipPassword`, and `BoardStoredShip` on the real bound `ship` service (`dotnet/src/Eve.Services.Space/ShipService.cs:297-397`). `AgentRpc` supplies FitShips with a provider that checks station service 17 or persisted structure fitting-service access (`dotnet/src/Eve.Host/Rpc/AgentRpc.cs:219-234`). `SpaceComposition` supplies persisted deployable records to SetShipPassword (`dotnet/src/Eve.Host/Composition/SpaceComposition.cs:495-501`).
- FitShips validates the active docked location and fitting service, derives required item types from the SDE-backed fit, assembles one requested packaged hull at a time and invokes `FitFitting`; its mutations use the existing `CharacterShips`/inventory transaction path (`dotnet/src/Eve.Services.Inventory/InvBrokerService.Fitting.cs:26-181`, `dotnet/src/Eve.Ships/CharacterShips.Assembly.cs:51-91`).
- Scoop validates scene, distance, item type, ownership, selected hold and capacity. Secure containers check the supplied password; ordinary container item moves and their space-row removal share one transaction. Mobile Depot contents are persisted in a new Cargo Container at the depot pose, and deployment removal is included in the same transaction (`dotnet/src/Eve.Services.Space/SpaceContainers.Scoop.cs:18-179`, `dotnet/src/Eve.Ships/CharacterShips.SpaceScoop.cs:17-163`). Migration `0032_mobile_depot_kind.sql` admits the already-supported `mobile_depot` deployed kind.
- Ordinary scoop emits item-change messages in client order. Mobile Depot recovery sends the ejection container and its contents before the depot; structure artifact scoop retains its prior dogma notification path (`dotnet/src/Eve.Services.Ships/ShipNotifications.cs:58-103,138-161`).
- BoardStoredShip checks bay visibility/access, range, target hull and contents, and storage capacity. It moves the stored hull and prior non-capsule hull and updates the character's active ship in one PostgreSQL transaction, then applies the simulation/session transition and returns activation state (`dotnet/src/Eve.Services.Space/SpaceContainers.MaintenanceBay.cs:218-353`, `dotnet/src/Eve.Ships/CharacterShips.Space.cs:503-629`, `dotnet/src/Eve.Services.Space/SpaceSessions.BoardStored.cs:13-119`).
- SetShipPassword checks the active pilot and scene, caches the credential for the session, matches persisted online control-tower hashes and updates the active ship harmonic. Hash creation and checking now use EveJS-compatible scrypt, with constant-time digest comparison (`dotnet/src/Eve.Services.Space/SpaceSessions.cs:182-231`, `dotnet/src/Eve.Services.Space/StarbasePasswordHash.cs`, `dotnet/src/Eve.Services.Space/SpaceContainers.PosMgr.cs:140-152`).
