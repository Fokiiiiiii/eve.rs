## Attack-surface review

- **Inbound session resource bounds:** The Host rejects inbound frames above 16 MiB. Session actors enforce both a pending-packet limit and a configurable pending-byte limit (`EVE_MAX_PENDING_BYTES_PER_SESSION`, default 16 MiB), counting the packet currently being dispatched, and await one decoded RPC dispatch at a time. Exceeding either inbound queue limit disconnects only the overloaded session. A Host regression covers an over-budget inbound frame. Outbound session notification queues cap at 512 packets and 8 MiB, with a connection-wide cap of 8,192 packets and 64 MiB; a Host regression verifies an over-budget session is disconnected. XMPP group chat limits bodies to 2 KiB and one message per character every 750 ms; private invitations are limited to one per character per second; message and invitation cadence timestamps are removed when the active link disconnects.
- **Expensive RPC rate bounds:** `PacketDispatcher` charges weighted per-session work units within a rolling minute for market order/region reads, multi-buy and batched type-history reads, inventory and asset enumeration, corporation and alliance member/owner enumeration and tracking, `corpRegistry.GetNumberOfPotentialCEOs` roster reads, shareholder queries and dividend payouts, `corpRegistry.ExecuteActions` role mutations, bounded corporation contact and member mutations, recent corporation kill/loss reads, personal and corporation wallet journal reads, wallet ISK transfers, LP store offer reads and purchases, all `contractProxy` list, history, escrow, and mutation RPCs, bulk bookmark operations, `GetAllInfo`, mailbox reads, status changes and sends, mailing-list operations, corporation recruitment search, fleet broadcast fanout, and structure-directory docking ACL queries and skill item injection, injector use, and extraction. `structureDirectory.CheckMyDockingAccessToStructures` and `GetMyDockableStructures` cost 10 units; `skillHandler.InjectSkillIntoBrain`, `InjectSkillpoints`, and `ExtractSkills` cost 10 units; the former caps raw IDs at 500 before callback work. Inventory RPCs cost 2 units so normal open-and-read flows fit the 120-unit default; `EVE_MAX_EXPENSIVE_RPC_UNITS_PER_MINUTE` configures that limit. A named `SessionRpcBudgetExceeded` response refuses calls beyond the budget; costs use the resolved service name so named-service and bound-object calls share the same per-session policy. Dispatcher regressions cover market calls, inventory, corporation `ExecuteActions` and potential-CEO roster reads, corporation and alliance enumeration (including ranked alliances), character killmail pages, wallet, LP store, mailbox and mailing-list operations, recruitment search, fleet broadcast fanout, structure docking ACL queries, skill item operations, and window reset.

### Findings fixed

- **Unbounded pending handshakes — denial of service.** `crates/eve-net/src/server.rs` spawned a task for every accepted socket; the handshake timeout limited each task’s lifetime but did not limit concurrent unauthenticated tasks. The listener now admits at most 256 concurrent handshakes and closes excess sockets. A slot is released once authentication completes or the handshake ends. Regression coverage: `pending_handshakes_are_capped_until_a_slot_is_released` verifies rejection at capacity and recovery after a slot is freed.
- **Mutable GitHub Actions references — supply-chain exposure.** `.github/workflows/ci.yml` and `.github/workflows/live-slow.yml` previously referenced version tags and `dtolnay/rust-toolchain@master`, allowing the action code to change without a repository change. The workflows now use full commit IDs with the release/channel recorded in comments. Regression coverage: `tools/headless-client/tests/test_workflow_security.py` checks that every workflow action uses a full commit ID and rejects `pull_request_target`.
- **Mutable Docker base tags — supply-chain exposure.** `Dockerfile` previously selected Rust and .NET base images by version tags alone. Each `FROM` now pins the image manifest digest alongside its version tag. Regression coverage: `tools/headless-client/tests/test_workflow_security.py` requires a SHA-256 digest for every base image.
- **Unbounded LP store singleton grants.** Purchase quantity could reach one million, and singleton offers generated one item row and notification per unit. Generated singleton items now cap at 256, and LP store reads and purchases consume the per-session expensive-RPC budget. `LpStoreMgrServiceTests.A_singleton_offer_cannot_expand_into_an_unbounded_item_grant` verifies a 257-item offer changes neither inventory nor purchase history; `DispatchGoldenTests.Loyalty_store_calls_have_a_named_per_session_budget` covers the named budget refusal.
- **Unbounded and malformed direct-trade RPC inputs.** `trademgr.MultiAdd` could stage one database transaction per supplied item, `MakeOffer` enumerated caller-supplied manifest collections without a count limit, and non-finite or out-of-range amounts could throw during decimal conversion. The service now caps bulk item and manifest inputs at 256, requires positive item identifiers, and maps malformed or out-of-range ISK values to a named refusal. Regression coverage: `TradeMgrRpcTests.Bulk_trade_item_lists_are_bounded_and_require_positive_ids` and `TradeMgrRpcTests.Trade_manifests_reject_non_finite_and_overflowing_isk_amounts`.
