# Inventory, hangars, assets and containers: deep fix

## Finding and fix

V24.01's ordinary inventory UI offers `SplitStack` for a stack larger than one at `eve/client/script/ui/services/menusvc.py:208-209`. Its only ordinary inventory caller is `eve/client/script/ui/services/menuSvcExtras/invItemFunctions.py:385-403`: it accepts one selected item, caps the quantity popup at the current stack size, resolves the station, raises `CanOnlyDoInStations` if there is none, then calls `GetInventoryMgr().SplitStack(stationID, itemID, qty, ownerID)`. It invalidates that owner's station cache after the call; for corporation assets it also adjusts the local source quantity and emits `OnCorpAssetChange`. The inventory manager is obtained from the station or solar-system inventory moniker in `eve/common/script/net/eveMoniker.py:122-132` and `eve/client/script/environment/invCache.py:424-426`. A separate contract UI call at `eve/client/script/ui/shared/neocom/contracts/contractentry.py:423-434` and `contracts.py:691-696` is not this InvBroker operation.

Before this change, eve.rs had no InvBroker `SplitStack` route. The client call therefore could not split a stack. The route is now registered through the existing Host inventory factory (`dotnet/src/Eve.Host/Rpc/InventoryRpc.cs:44`, `dotnet/src/Eve.Host/Persistence/Inventory/HostInventoryServiceFactory.cs:39`; the global-assets broker is also created by `CharacterRpc.cs:48`). `InvBrokerService.SplitStack` at `dotnet/src/Eve.Services.Inventory/InvBrokerService.cs:1453-1484` accepts the client's four positional arguments, checks station/session, item ownership and quantity, and requires both take and deposit rights for corporation hangars. `CharacterShips.SplitStackAsync` at `dotnet/src/Eve.Ships/CharacterShips.cs:110-136` locks the character and item in a transaction, verifies the docked station and allowed location/flag, and delegates the split to the existing transactional item store (`dotnet/src/Eve.Inventory/Items.cs:524-540`). The item store reduces the source and creates a second stack under the same owner, location and flag.

The regression was reproduced by temporarily removing the route's `[Method("SplitStack")]` registration and running the focused DB test: it failed because the original stack stayed at 12 instead of the expected 7. The route registration was restored, and the same test passed.

On success, the RPC returns `None`, matching the client call's use of the remote result only as completion. The ship notification helper sends no dogma event for this operation and emits the two item rows in source-then-created order through `OnItemsChanged` (`dotnet/src/Eve.Services.Ships/ShipNotifications.cs:87-114`). The UI then invalidates its location cache; the corporation-specific local quantity adjustment/event remains the client's post-call behavior. Failure paths retain the client's station error and return `FakeItemNotFound` for a missing, foreign, singleton, or unsplittable stack.

## Adjacent core flows inspected

- Asset browsing: `assetsWindow.py:440-457` loads station summaries with global `ListStations`; `assetsWindow.py:745-765` requests `ListStationItems(stationID)` when expanding a location. Current EveJS has the corresponding global-assets implementation at `server/src/services/character/charMgrGlobalAssets.js:589-601`. Existing DB coverage includes personal station assets and nested containers in `InventoryServiceTests.Global_assets_bind_lists_personal_station_assets_and_nested_container_items` (line 636) and structure-root assets in the following test (line 664). No additional mismatch was established in this pass.
- Moving items and fitting: the everyday container drop calls `MultiAdd` from `invCache.py:1027-1063`; the inventory controller uses it at `invControllers.py:489-565`, and the inventory window routes drops at `ui/shared/item.py:958-1080`. eve.rs handles the route at `InvBrokerService.MultiAdd` (line 1486 onward), with the transaction-backed ship/item movement path in `CharacterShips.MoveAsync` (line 138 onward). EveJS has a large matching handler at `server/src/services/inventory/invBrokerService.js:13376-14126`. This review found no specific behavioral defect here.
- Wreck loot: the client checks criminal-take permission and cargo capacity before raising `OnWreckLootAll` (`invControllers.py:1353-1366)); `invWindow.py:1244-1250` consumes it to close/advance the wreck entry and blink cargo. No notification-order discrepancy was confirmed in the inspected path.

## EveJS, mechanics and evidence limits

The current EveJS 261028.1 ordinary InvBroker has `Handle_MultiAdd` but no `Handle_SplitStack` in `server/src/services/inventory/invBrokerService.js`. Its only exact-name handler found is `server/src/services/_other/contractProxyService.js:910-913`, which records a contract audit event and returns null; it is not the station inventory operation. The client callsite and its post-call cache work therefore define the required ordinary stack-split behavior. This difference is recorded in `docs/reference/compat/DEVIATIONS.md`.

Splitting creates no SDE-derived statistic or gameplay formula: the client quantity selector supplies the amount, and the server enforces the authoritative stack and ownership. EVE University documents splitting commodity stacks by shift-drag in Planetary Industry ([Colony management](https://wiki.eveuniversity.org/Colony_management)); that corroborates the UI concept but does not specify this RPC.
