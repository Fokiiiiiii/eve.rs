# Host input hardening handoff

## Change
- `CallRequest.Decode` expands tuple positional arguments and rejects a Python list in the outer args slot. `PacketDispatcher` answers an unreadable CALL_REQ with wrapped `exceptions.UserError("UnMachoDestination")`.
- `HostServer` disconnects the affected session with `InvalidPacket` after marshal or dispatch failures. Frame reading already rejects truncated and over-limit frames.
- Added dispatcher tests for malformed CALL_REQ replies, tuple positional arguments, rejection of a top-level list, and acceptance of a nested list with `machoVersion`; added host tests for malformed marshal packets, truncated frames and oversized frames. The Host socket test verifies a top-level list receives a wrapped error without invoking the service, then verifies a nested list succeeds. The unknown-service integration assertion remains in `HostServerTests`; the session-open test asserts the initial notification is first.
- The R14 audit revisited commit `b213ee17`'s flattened-list golden row. The fixture now records EveJS's actual nested-list response. The V24 client normally constructs args from `*args` as a tuple (`ServiceCallGPCS.py:675-688,230-234`); `CallUp` passes the received value to native `ClockThisWithoutTheStars` (`ServiceCallGPCS.py:120-132`), whose behavior for a malformed list container is not established by the available Python source. eve.rs rejects that out-of-contract top-level list. The golden test records this intentional difference from EveJS's single-list fallback (`docs/reference/compat/DEVIATIONS.md`).
