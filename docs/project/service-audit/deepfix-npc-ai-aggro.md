# NPC AI, aggro, spawning, bounty, and loot deep check

## Change

`DynamicBountyMgrService.GetOutputForClientSolarSystem` reads durable Host state and returns the V24.01 pair `(PyReal output, PyBool active)`. Eligible systems without a persisted row read as equilibrium `(1.5, true)`; systems outside DBS coverage return `(1.0, false)`, as does a missing reader. `GetDBSMapData` now returns every SDE-eligible system, including systems at equilibrium. NPC bounty settlement multiplies the base by the NPC profile's optional `bountyPayoutMultiplier` (default 1) and current system output, rounds the gross amount to ISK cents, then divides the gross between the pilot and ESS before the payout bucket is committed. The gross DBS input and ESS credit share commit atomically with the pilot bucket. Qualifying player ship losses are keyed idempotently and recorded with ship destruction; the durable daily job advances and commits system state before notifying sessions in that system. EVE University states that the Bounty Risk Modifier multiplies NPC bounties, rises after player losses, falls after NPC kills, and drifts toward equilibrium ([NullSec Ratting](https://wiki.eveuniversity.org/NullSec_Ratting)). The Wiki does not give numerical control terms, so the step policy follows EveJS 261028.1 (`dynamicBountyPolicy.js:10-24`). Its `bountyRuntime.js:448-515` computes 1,000,000 × 1 × 1.5 = 1,500,000 ISK before the ESS split.

Evidence: V24.01 `eve/client/script/ui/shared/dynamicResource/dynamicResourceSvc.py:59-65` returns `(1.0, False)` when DBS is emergency-offline and otherwise unpacks the RPC pair; `:160-165` primes the cache as `(rate, True)` on the state notification. `eve/client/script/ui/shared/infoPanels/infoPanelLocationInfo.py:319-326` displays percentage output only when active. Current EveJS `src/server/src/services/dynamic/dynamicBountyMgrService.js:12-22` returns a marshalled real plus a boolean; `dynamicBountyRuntime.js:31-35` returns `(1, false)` outside coverage and equilibrium output with `active=true` for covered systems without a state bank. EVE University describes system bounty risk modifier as a multiplier applied to NPC bounties, varying with system activity: [Ratting](https://wiki.eveuniversity.org/Ratting).

The whole-client search found one caller of `GetOutputForClientSolarSystem`, in `dynamicResourceSvc.py:59-65`; consumers are its local cache/update event and the location info panel above. The response carries no user-facing error code, and the client simply hides the value while inactive. Session changes clear the cache and scatter the local update at `dynamicResourceSvc.py:175-182`; global emergency-offline changes do the same at `:184-191`.
