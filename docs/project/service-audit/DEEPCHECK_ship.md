Checked against V24.01 client build 3396210 at `/home/user/eve-logic` (tree `1dbb5711a072a146e1d228365668ac05655eefe1`), current Host source, and EveJS 261018.1 at `/home/user/evejs-261018.1/src`. ## Route and argument transport

Production composition adds `ShipService` to the agent service list only when `spaceSessions != null` (`dotnet/src/Eve.Host/Rpc/AgentRpc.cs:109-110`; service-list order at `CharacterServiceList.cs:54-67`). The method routes are the `[Method]` declarations in `dotnet/src/Eve.Services.Space/ShipService.cs` and `ShipService.Drop.cs`.

The V24 `GetShipAccess()` moniker binds to the station or solar-system place (`eve/common/script/net/eveMoniker.py:42-50`). Generic moniker calls send `MachoBindObject((place, group), (method, args, kwargs))` (`carbon/common/script/net/moniker.py:120-160`; `carbon/common/script/net/ServiceCallGPCS.py:65-115`). The object-call path injects `machoVersion=1` in kwargs (`carbon/common/script/net/ObjectCallGPCS.py:385-415`). Host `Binding.NestedAsync` accepts tuple/list argument collections and forwards the nested kwargs (`dotnet/src/Eve.Services.Space/Binding.cs:40-56`). Existing socket tests exercise outer and nested `machoVersion` for GetShipFittingInfo, GetDirtTimestamp, Drop, and LaunchDrones (`ShipRpcHostTests.cs:12-44`; `MoreShipRpcHostTests.cs:50-89`).
