# Tournament public relocation: implementation and verification

Real simulator combat exposed a relocation defect: a referee's ship had shield charge 0.9237595794813858 before travel and 1.0 afterwards because the destination was entered using the older database ship snapshot. The public-scene move now transfers the live resident ship in the simulator, preserving its live condition, and uses a correlated operation ID and a fingerprint for in-process retry. Original Abyssal authorization remains in place. Acknowledged move condition is saved using a fitting-store revision CAS; the revision persists even when a full-condition write removes the condition row, and the existing incapacitated flag is retained. The pending state remains set until persistence succeeds.

Validation in local development PostgreSQL and the real `eve-sim` binary:

- Host project build: 0 warnings, 0 errors.
- Rust `public_moves_keep_live_condition_and_replay_only_matching_operation`: 1 passed, 0 ignored. Covers live condition, same-scene and cross-scene moves, same-operation replay and conflicting reuse.
- Fitting `Ship_condition_revision_*`: 2 passed, 0 skipped. Covers full-reset ABA, rollback, stale revision, and two competing transactions.
- Shared SimLink corpus: Rust 13 passed, 0 ignored and C# 406 passed, 0 skipped, including kinds 132–139, wreck absence/errors, malformed wreck guards, invalid move IDs and non-Enter nested frames. Dedicated GUID encoder checks passed once in each language.
- `TetherPolicyTests.Conduit_refuses_a_passenger_with_an_unresolved_public_move_before_simulation`: 1 passed, 0 skipped. Two database-backed sessions and the real SpaceSessions service use a recording FakeSim. Before the guard a conduit command was sent for a pending passenger (1 instead of 0); after it, the command is refused and a no-passenger control is sent. This is not a real simulator conduit-jump test.
- Host `Referee_travel_restores_real_space_origin_and_survives_bound_release`: 1 passed, 0 skipped. It damages the ship in the real simulator, moves and returns it, checks live shield/armor/hull, verifies persisted shield/armor/hull, and verifies an existing incapacitated flag survives. Before condition persistence the same test failed twice because the database condition row was absent. Earlier before the live-transfer implementation the actual shield charge reset to 1.0.

Simulator and host move receipts are in memory, not durable exactly-once records. The existing tournament journals carry separate persisted operation IDs; restart and lost-reply reconciliation require their own evidence. A move that remains pending rejects another relocation and several direct movement, module, repair, cyno, wormhole, drone and fighter actions, but the complete mutation surface has not been established. The real-simulator referee test also passed with a deliberately dropped successful move reply, rejected movement and targeting while pending, then retried the same persisted operation ID after its lease expired. The same test injects a PostgreSQL condition-save failure after a successful simulator acknowledgement: before the fix, retry saved the condition but emitted zero destination SystemEntered notifications; after the fix it emits exactly one, and an ordinary same-operation replay emits no extra notification. The same test now also enters a docked character in the real simulator, drops its successful entry reply, checks the live body and database both remain in the destination, blocks a pending command, and retries the same operation successfully. Before the fix that body was live in system 30000144 while the database put the ship back in station 60003760. The test does not restart the host or simulator. Inventory SetLabel and mutable inventory entry points now have an explicit pending guard: the real-simulator lost-reply test passed through the actual SpaceContainers and InvBroker services, verifying SetLabel and Add refuse and the stored name remains unchanged. The existing docked SetLabel test also passed (1 passed, 0 skipped). Gated-fighter controls and integration after bound-object cleanup changes also remain pending. A successful in-process simulator receipt confirms operation fingerprint and resident ship/session in the destination, not that later physics left the ship at its requested pose. The tournament caller verifies the actual position against its arena; a mismatch retains the journal and does not guarantee automatic repositioning. The docked-entry proof is limited to a lost reply within the same Host and simulator processes. Their entry receipts and pending context are in memory; restart while the simulator body survives is not reconciled by this test. A definitive entry refusal currently leaves the operation pending. Pending docked contexts retain their session for reconciliation; safe cleanup after session close has not been established. Relocation serialization gates use weak session keys and do not retain completed sessions solely because a move occurred. The public-to-dock boundary is distinct from both tested moves. Protocol 87 requires ASCII GUID D form; the Host normalizes IDs to lowercase and simulator receipts compare exact supplied text, so alternate GUID encodings are incompatible. These results do not establish graphical EVE client verification or a full test-suite pass.
