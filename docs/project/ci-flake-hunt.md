# CI flake hunt

Base checked: `c2ba5c9c7bcea603dc1c941782fb37608ced82ea` (`origin/main`). The named EventBus, raffle and Space test changes were already present as unstaged diffs in `cx3`. The supplied `cx4` worktree was inspected and contained separate space-combat work, but not those changes or the referenced handoff note; `cx4` was left untouched.

## Fixed

- **EventBus shutdown during PostgreSQL work.** The pump passed its stop token to the subscriber-ensure `INSERT` and the housekeeping cursor `UPDATE`. A cancellation could interrupt the statement before the transaction advanced its cursor. The empty-subscriber path now lets the short `UPDATE` and its commit finish, and subscriber ensure lets its idempotent `INSERT` finish after a connection is acquired. Both new tests install a PostgreSQL trigger with `pg_sleep(0.75)` before starting the pump, hold the command in flight, then stop the bus. In one controlled run with the original `EventBus.cs` from `c2ba5c9`, the housekeeping regression test failed with cursor `1` expected and cursor `0` observed. With the fix, both tests passed 20/20 each. The change preserves event delivery order and payloads.
- **Raffle expiry lock test timeout.** The test previously polled 500 times at 10 ms, giving a slow runner about five seconds to schedule both lock waiters. It now uses one bounded 30-second deadline and retains the assertion that both expiry transactions must be waiting on the locked raffle row before the lock is released. The database-backed test passed 20/20.
- **Space test transition ordering.** `A_dock_returns_nothing_for_an_accepted_command_and_when_it_is_refused` now waits for `IsSessionChanging(session)` to become false before binding the Beyonce object. This waits for the host transition that `InSpaceAsync` starts to finish before the next RPC. It passed 20/20, plus one extra confirmation run.
- **Recorded character-name collisions.** Live tests used 10 hexadecimal characters from a UUID for run-scoped names. `tests/runid.py` now uses 21 hex characters (80 random bits for UUIDv4), and `test_login_to_character.py` uses that shared helper. The shared helper also serves tests that append one character to the token, so `Recorded Pilot ` plus 21 hex characters and that suffix stays within the 37-character client limit. The standalone `trace_replay.py` scenario uses 22 characters (84 random bits), exactly 37 characters after the `Recorded Pilot ` prefix.

## Character-name evidence

V24.01 caps the name field at 37 characters (`/home/user/eve-logic/eve/common/lib/appConst.py:2177`; the name editor uses it at `/home/user/eve-logic/eve/client/script/ui/login/charcreation_new/steps/sections/chooseNameSection.py:64`). The picker sends candidate names to `charUnboundMgr.ValidateNameEx` (`chooseNameSection.py:184-189`). The creation container calls `CreateCharacterWithDoll` (`/home/user/eve-logic/eve/client/script/ui/login/characterCreationContainer.py:1836-1842`), through `ccSvc` (`/home/user/eve-logic/eve/client/script/ui/services/ccSvc.py:92-98`). The alternate creation container has the same call at `characterCreationContainer_new.py:1297-1301`.

The recording generator creates `Recorded Pilot {run}`, checks that it is taken, then deliberately attempts to create it again and records an error (`tools/headless-client/scripts/record_character_scenarios.py:135-145`). Thus the duplicate-key line for `recorded pilot 81d53f5c8b` in CI run [43678391981](https://github.com/Fokiiiiiii/eve.rs/actions/runs/43678391981) corresponds to the expected duplicate-name step (step 17), not a failing pytest assertion. The inspected log did not contain the example suffix `ae97d8c997`. The longer per-run token addresses accidental collisions between distinct test runs without removing or weakening the deliberate duplicate-name check. EveJS 261108.1 normalizes names and returns `UNAVAILABLE` when the normalized key already exists (`server/src/services/character/characterNameRuntime.js:242-267`); its `ValidateNameEx` handler delegates to the same validator (`server/src/services/character/charService.js:1977-1983`). No client protocol or gameplay behavior changed.
