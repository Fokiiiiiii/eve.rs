# Wormhole audit fixes

Read-only audit: `/home/user/reports/90-audit-eve-wormholes-r14.md`. I checked every finding against the local V24.01 client (`/home/user/eve-logic`), EveJS v0.12.9 (`/home/user/evejs-261028.1`), and the current Host, database, and simulation paths before changing code.

## Findings and disposition

All seven findings were confirmed; none were skipped as false.

1. **Wormhole slim fields and state updates — confirmed and fixed.** V24's wormhole object reads `nebulaType` and its debug call reads `wormholeSize`, `wormholeAge`, and `maxShipJumpMass` (`eve/client/script/environment/spaceObject/wormhole.py:15-29`); its info panel reads class, age, size, and ship-mass category (`eve/client/script/ui/shared/info/infoContentBase.py:1517-1548`). EveJS derives the same fields in `server/src/services/exploration/wormholes/wormholeRuntime.js:603-659,690-695`. eve.rs now derives nebula from SDE `mapRegions.nebulaID`, derives age/size/mass category from stored state, carries the fields through Host placement and simlink encoding, and updates both live ends after mass or age-bucket changes. Regression coverage: `A_jump_is_taken_by_the_simulation_places_the_destination_end_and_polarizes_the_pilot_so_the_second_try_is_refused`, `A_durable_age_bucket_transition_updates_both_wormhole_ends_in_the_simulation`, plus Rust slim/notification tests.

2. **Return jump polarization — confirmed and fixed.** V24 queries polarization using the wormhole end's `itemID` when it enters space (`spacecomponents/client/components/jumpPolarization.py:19-37`). EveJS documents that polarization applies to the hole and records both endpoints (`wormholeRuntime.js:2181-2198`). eve.rs now stores polarization by character and connection, so lookup at either end blocks the immediate return. Regression coverage: `A_pilot_is_polarized_at_the_arrival_end_and_cannot_immediately_jump_back`.

3. **Polarization lost on restart — confirmed and fixed.** EveJS persists polarization through its game-store owner (`wormholeRuntimeState.js:613-635,675-690`; `gameStore/tableOwnership.js:283-285`). eve.rs now persists character, connection, and expiry in migration `0002_polarization.sql`; jump validation and polarization lookup use the same store. The jump service regression reopens the world/store and verifies the arrival-end polarization remains available.

4. **Transit after expiry but before scheduler execution — confirmed and fixed.** EveJS checks expiry during jump preparation (`wormholeRuntime.js:2093-2096`). eve.rs now checks expiry under the connection row lock in the same transaction as jump validation, collapses the expired connection, cancels its expiry job, commits, then removes the sim ends and returns the V24 cancel result. Regression coverage: `An_expired_connection_is_collapsed_and_the_registered_rpc_sends_the_client_cancel_notification`.

5. **Collapse/replacement sim updates before database commit — confirmed and fixed.** The scheduler previously let wormhole expiry publish through `Changed` while its job transaction was still open. Expiry and static-respawn notifications are now scheduler after-commit callbacks; direct jump/transit changes are also published after commit. A PostgreSQL trigger regression forces failure while the scheduler is completing the expiry job, verifies the database collapse and sim callback roll back together, removes the trigger, retries after the lease, and verifies one callback after the committed collapse: `Expiry_notifications_wait_for_commit_and_are_not_published_when_job_completion_rolls_back`.

6. **Collapsed-end cancel absent from the production Host path — confirmed, with scope clarified, and fixed.** The optional callback already existed in `WormholeMgrService`, but the production `SpaceRpc` composition omitted it; the direct space handler also treated a known collapsed end as an unknown stargate. The production composition now connects the pending-warp state, and the authoritative database jump path returns `PyNone` plus `OnWormholeJumpCancel` for collapsed or expired known ends. V24 handles that notification by clearing the action and showing `EnterCollapsed` (`eve/client/script/parklife/spaceMgr.py:94-98`); EveJS returns the cancellation for `WORMHOLE_COLLAPSED` (`wormholeMgrService.js:255-259`). Regression coverage includes the production-composition Host wire test and the database-backed stale-end RPC test.

7. **Static replacement delay — confirmed against the required EveJS behavior and fixed.** EveJS configures a 60-second static respawn delay (`config/world.json:2-6`) and stores the next time at collapse (`wormholeRuntime.js:954-972`). eve.rs now persists a keyed static-respawn job due 60 seconds after collapse; if no eligible destination exists, the durable job retries after the same delay. Lifecycle and Thera regressions assert the wait, restart durability, and free-end orientation.
