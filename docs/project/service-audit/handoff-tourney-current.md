## Fancy repair-rate policy

The V24 client multiplies the `totalReps` tuple value by 60 and draws it on the EHP bar scale (`eve/devtools/script/form_tournament.py:616–632`). The CCP Thunderdome guide, pp. 10–11, describes the Fancy UI generally but does not specify the repair-rate formula, damage profile, remote attribution, or passive shield recharge. Therefore this server’s chosen metric is explicitly a local policy, not a claim to reproduce CCP’s private formula: current running local repair capacity plus current running remote repair capacity targeted at an actual same-team ally, in raw HP per second. Inactive modules, passive natural recharge and actual healing delivered are excluded. Unknown necessary current input, including unavailable spool state, makes the metric family unavailable. Inputs must retain repair layer and target identity so later conversions can be evaluated without guessing. The existing EHP helper uses the V24 fitting convention of an equal four-damage resonance average per layer; that convention alone does not establish that CCP applies it to the Fancy repair bar. This describes the implemented policy; the focused live wire checks below establish the cases exercised, not every module family.

## State and operations

Host configures the tournament store and migrations, operators' imports, and Space callbacks in `dotnet/src/Eve.Host/Hosting/HostComposition.cs:171`, `:214`, `:230`, `:243`, `:360`. The JSON formats and zero-based region center beacon ordinal are documented in `tournament-configuration-import.md`. A region import is operator supplied and is not evidence that a placement is safe. Runtime placement and current scene checks remain necessary.

Countdown validates current two-team locked membership, saved point/fit errors, current active ship and contents against the locked hash, confirmed outbound journal and exact live public pilot. It temporarily blocks admission of movement/warp/lock commands while taking fresh actual pilot positions against the configured physical region, and rechecks the saved region/center and locked DB state before transition (`PersistenceTournamentMatches.CountdownValidation.cs:8`). This does not freeze simulation physics or commands already admitted: position is a point-in-time check, not an atomic physical freeze. A failed restriction refresh remains fail-closed pending scheduler repair. A committed countdown publishes an immutable camera notification snapshot and match update (`PersistenceTournamentMatches.Actions.cs:25`, `:205`). Exact public scene identity is checked in `dotnet/src/Eve.Services.Space/SpaceSessions.cs` by `IsInPublicSystem`.

Player status calculates each score as configured maximum points minus the opposing team's surviving locked ship points, equivalent to opponent unused points plus eliminated ship points, with no invented defaults when roster snapshots are incomplete (`PersistenceTournamentMatches.PlayerStatus.cs:34`). This follows CCP Alliance Tournament XXII Victory Conditions: https://www.eveonline.com/fr/news/view/alliance-tournament-xxii-rules-and-regulations . The actual committed death chain updates elimination and publishes status (`PersistenceTournamentMatches.Deaths.cs:60`). Outbox notifications use after-commit delivery; ordinary repeated calls do not create another transition event, while crash recovery is at least once, not exactly once.

The reference server repository recorded in AGENTS is `Fokiiiiiii/evejs-v0.12.9`, observed commit `7cc6f323c7c5c92c2738476a62768318799d8077`; tournament source path `server/src/services/tournament/tourneyMgrService.js`. Its relevant score/natural-ending behavior was found to be stubbed, so stub values do not establish real gameplay mechanics.

## Known unfinished work and limits

- `GetFancyDetails` can return six numeric aggregates per team, ordered `(current EHP, reps/sec, max DPS, applied DPS, max control, applied control)`. The server defines repair as raw HP/s of running local repairs plus running remote repairs targeting the same team. Control is the number of online fitted and running offensive EWAR sources in the supported CCP guide families; it is not a reproduction of CCP's unpublished weights. Applied DPS is actual post-resistance damage in a fixed rolling one-second window. Current EHP and applied damage come from one v89 native scene sample. Host fit, effective attributes, source identities and running state are observed before and after that sample and checked against the native fit and running state. This is stable observed spectator telemetry, not a linearizable cross-store transaction or authoritative winner/tiebreak input.
- Unknown, changing, unsupported or inconsistent inputs yield `None`, rather than a guessed zero. Inactive charge and heat use the stable Host state where native has no idle value; active native state must agree. Combat drone maximum DPS follows the pinned fitting client's bandwidth/active-count selection over stable bay and controlled-space identities; fighter maximum DPS follows primary and secondary tube abilities and the v90 native same-tick squadron count. A known zero-damage ability contributes zero, while unknown fighter member counts, active repair/control drone state, deployed EWAR fighter activation state, charged repair current-cycle state, and unsupported damage or repair families remain unavailable. A proven native destroyed identity with matching eliminated roster state contributes zero capacity and EHP; missing or departed identity remains unavailable. A manual match first observed after a death can remain `None` when no authoritative native death proof exists. A dedicated actual-wire destruction regression remains outstanding. The Rust `eve-space` tournament-filtered suite passed 29 tests with none skipped; the v89 and v90 codec golden tests were run separately.
- `AbyssalHostFlowTests.TournamentFancyWire` exercised the registered RPC with PostgreSQL and the v89 Rust simulator: six numeric values for both teams, then an actual locked and activated laser hit with positive red applied DPS and zero blue applied DPS. Real SDE focused tests cover loaded/empty/overheated guns, EWAR source counts, friendly versus enemy remote repair, charge agreement, ancillary uncharged repair, drone bandwidth/identity selection, and fighter tube/airborne counts. The fighter test checks SDE Fighters skill 23069 at levels 0 and 5 and a mutated damage attribute through the effective dogma world, as well as an unmapped non-damage ability yielding zero. v90 codec tests distinguish unknown, zero and valid 1–64 fighter member counts. A registered Fancy wire test with actual PostgreSQL and v90 Rust launches a real drone and an Archon squadron, verifies the native nine-member sample and stable maximum DPS across each launch, and observes a real laser hit. They do not establish CCP's private formula or GUI behavior. An initial active test produced a persistent `RUNNING_MISMATCH` but did not reproduce on subsequent runs; its cause is not established. A separately reproduced Ended-before-activation-reply race formerly resurrected Host running state: a deterministic FakeSim/PG test failed before the lifecycle fix and passed after it, and a second test verified that an old refusal does not remove a newer activation. Actual Fancy and remote-repair ACK regressions also passed after the fix. Do not claim the earlier intermittent mismatch was proven to have this cause.
- Automatic completion is opt-in via the operator's `alliance_tournament` policy; the default remains manual. At the deadline, only complete identity-matched authoritative cutoff evidence can settle an unequal score. Pending, unavailable, unknown, lost-history or tied evidence stays pending; the registered real-start/deadline test below confirms the tied case. Actual time-dilation/overtime effects and attack-bar tie-break adjudication are not implemented. Overtime level 0 represents the only currently supported level, not simulated overtime. CCP's guide describes manual controls and the 30-second countdown, two-second abort cutoff, and 60/65/70-second postgame actions; it does not establish the missing simulation effects.
- The current gate's fresh position plus admission mask does not atomically freeze the simulator. Test actual outside-region movement, concurrent pre-admitted commands, physics drift, reconnect and mask repair. Some stored override/lock, release/rebind, player return and recovery cases still lack the complete registered client-to-host-to-sim workflow or graphical-client validation.
