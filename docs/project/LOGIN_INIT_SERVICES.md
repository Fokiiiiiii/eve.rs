# Login and Initial World Entry RPC Inventory

Scope: V24.01 build 3396210, from the front handshake through character selection and the first world session. This inventory combines the live client callsites, `oracle/fixtures/scenarios/login_to_character.json`, `docs/reference/spec/services.tsv`, current Host service registration, and the matching EveJS runtime path. `Implemented` means the route has a concrete server implementation; `Partial` means the route exists but a path returns a default or does not cover the full client behavior; `Missing` means no route was found; `Not applicable` means the client callsite review shows the service is not part of the login phase. Headless verification is listed separately from graphical-client verification.

## Client entry sequence

The headless login-to-character walk (`tools/headless-client/tests/test_login_to_character.py`) validates the front handshake/session initialization, creates characters, fetches selection rows, rejects cross-account character selection, selects an owned character, and checks `machoNet.GetTime`. V24.01 callsites include `eve/client/script/ui/login/charSelection/characterSelection.py`, `eve/client/script/ui/services/ccSvc.py`, `eve/client/script/ui/login/characterCreationContainer.py`, and `eve/client/script/ui/login/characterCreationContainer_new.py`. Selection invokes `sessionMgr.PerformSessionChange(... charUnboundMgr.SelectCharacterID ...)`; the Host installs the selected character state and emits the session change through the existing session path.

### Seasonal campaign configuration

Set `EVE_SEASONAL_LOGIN_CAMPAIGN` to a JSON object with positive `campaignId`, ISO `startDate` and `endDate`, UTC `turnoverTimeUtc`, boolean `retroClaimEnabled`, and nonempty `alphaRewards` and `omegaRewards` maps. Each reward map uses zero-based day indexes with positive `typeId` and `quantity`. The campaign is inactive when the setting is absent or its dates do not include the current reward date. Reward types are checked against the loaded item catalog before a claim is committed. Claim dates are stored in `seasonalLoginCampaignProgress`; redeem tokens and claim history are written in one transaction.

Set `EVE_LOCALIZATION_TEXT_CHANGES` to a JSON array of exactly three maps. Map values may be nested JSON objects, arrays, strings, numbers, booleans, or null; the Host converts them to the matching Python marshal values. An absent setting returns the three empty maps used by EveJS 261018.1. Populate these maps from the deployment's text-change catalog.
