## Composition, state owners, and notification path

InventoryRpc() wires the services to the active mailCache, Postgres item source, character directory, SDE reader, item mutation service, dogma state, item types, ships and skin catalog. The IndustryMonitorRpcService is constructed without an availableMaterials delegate, so its actual runtime path is the in-class item-store fallback. The skin callbacks are also live Host wiring: skin application sends OnShipCosmeticsChanged and OnCurrentShipSkinChange; license activation sends OnSkinLicenseActivated; consumed inventory sends OnItemChange (InventoryRpc.cs:45-72). Dynamic-item creation sends item-change notifications after the mutation service commits (DynamicItemRpcService.cs:67-79).

Authorization is implemented inside these service bodies. `GiveSkin` now requires a staff account role in Host; EveJS still has no staff-role check. `GMExpireSkinLicense` now requires GML in Host; EveJS still has no role check. Their client entry points are developer skin menus, which do not protect direct RPC calls.


The actual compatibility cache is a World writer with an OwnerSession, not a passive reader. LegacyGameStoreComposition loads characterEnergyState, shipCosmetics, shipLogoFittings, planetRuntimeState and industryRuntime before the services are constructed. GameStoreCache is a partial type: Write/RequireWriter live in GameStoreCache.Write.cs and ScheduleFlush lives in GameStoreCache.Flush.cs. Write success means the cache mutation was accepted and a background flush was scheduled; it is not the acknowledgement of a database commit. This distinction applies to skin, launch and monitor persistence (../../../dotnet/src/Eve.Host/Composition/LegacyGameStoreComposition.cs:58-83; dotnet/src/Eve.GameStore/GameStoreCache.Write.cs:52-147; dotnet/src/Eve.GameStore/GameStoreCache.Flush.cs:242-251).

The current PacketDispatcher has no blanket GM/ownership guard for these calls. It preserves wrapped user errors; unexpected non-cancellation exceptions become a correlated wrapped failure (or strict-RPC failure), not a raw database message to the client. The six handlers' own checks therefore matter (../../../dotnet/src/Eve.Services/PacketDispatcher.cs:76-247).

## Fixed response DTOs

### Character energy

GetMyEnergyState returns the characterenergy.characterEnergyState.CharacterEnergyState Ex1 object whose list has, in order:

1. energyLevel
2. lastRechargeTickTimestamp
3. energyIncreasePerRechargeTick
4. rechargeTickPeriod
5. minEnergyLevel
6. quiescentEnergyLevel

Normal defaults match the reference: minimum 0, capacity 100, increase 1, recharge period 792 seconds. Invalid persisted zero/negative recharge values use different minimum-positive constants in .NET and JavaScript. The read computes recharge through the current filetime but does not persist a new state or send a notification (CharacterRpcServices.cs:9-52; EveJS characterEnergyMgrService.js:21-24,102-113,296-309).

### Paper doll portrait row

GetPaperDollPortraitDataFor returns a two-element sequence: a list containing zero or one packed row, followed by None. The row has these 37 columns, in order:

cameraX, cameraY, cameraZ, cameraFieldOfView, cameraPoiX, cameraPoiY, cameraPoiZ, backgroundID, lightID, lightColorID, lightIntensity, portraitPoseNumber, headLookTargetX, headLookTargetY, headLookTargetZ, headTilt, orientChar, browLeftCurl, browLeftTighten, browLeftUpDown, browRightCurl, browRightTighten, browRightUpDown, eyeClose, eyesLookVertical, eyesLookHorizontal, squintLeft, squintRight, jawSideways, jawUp, puckerLips, frownLeft, frownRight, smileLeft, smileRight, renderStatus, paperdollState.

The integer columns are backgroundID, lightColorID, lightID, renderStatus, paperdollState, and portraitPoseNumber (DB type 3); the other columns are type 5. Both implementations expose the same names and order (CharacterRpcServices.cs:57-63,114-126; EveJS paperDollServerService.js:27-76,125-133).

### Paper doll appearance payload

There is no fixed property list for the appearance DTO: Host decodes and recursively preserves the stored marshal value, normalizing sculpting data. When a sculpting payload contains sculptLocationID and at least one recognized weight field, the recognized weight fields are weightUpDown, weightLeftRight, and weightForwardBack; missing/None weights normalize to numeric zero. A sculpting row header is padded to five entries and header positions 2-4 normalize None to integer zero (CharacterRpcServices.cs:144-223). Other payload fields remain data-dependent.

### Ship cosmetics license KeyVal

The common license KeyVal has exactly: skinID, expires, isSingleUse, licenseTypeID, skinMaterialID, materialID. expires, licenseTypeID, skinMaterialID, and materialID may be None; materialID mirrors skinMaterialID (ShipCosmeticsMgrRpcService.cs:260-273; EveJS shipCosmeticsMgrService.js:53-67).

### Dynamic-item KeyVal

GetDynamicItemInfo returns these 11 fields: itemID, typeID, sourceTypeID, sourceItemID, mutatorTypeID, mutatorItemID, characterID, createdAtMs, attributes, modifiers, baseAttributes. The last three are numeric dictionaries keyed by attribute ID (DynamicItemRpcService.cs:81-104,131-149; EveJS dynamicItemService.js:278-302).

### Planet rowsets

GetPlanetsForChar returns a CRowset with five type-3 columns: solarSystemID, planetID, typeID, numberOfPins, celestialIndex.

GetMyLaunchesDetails returns a CRowset with ten columns: launchID type 3, solarSystemID type 3, itemID type 20, ownerID type 3, planetID type 3, status type 17, launchTime type 64, and x, y, z type 5. Host and EveJS descriptors agree (PlanetMgrRpcService.cs:13-19,97-115; EveJS planetMgrService.js:65-83,495-517).

### Industry monitor response

ConnectJob returns a Python tuple: monitorID, then availableMaterials, a dictionary of integer typeID keys to integer quantities. EveJS native arrays are encoded as PyTuple, not PyList (evejs-v0.12.9/server/src/network/tcp/utils/marshal.js:213-217). Thus the earlier tuple/array finding was a false positive. The portrait outer sequence is also a tuple on both sides. DisconnectJob returns None (IndustryMonitorRpcService.cs:33-59; EveJS industryMonitorService.js:20-33).
