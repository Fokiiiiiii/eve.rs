# facWarMgr 深掘り監査（V24.01）

監査日: 2026-10-27

## 結論と対象

V24.01 クライアントに正確なリモート名 `facWarMgr` がある。`eve/client/script/ui/services/facWarSvc.py:47-50` のプロパティが `sm.RemoteSvc('facWarMgr')` を返し、通常の Macho リモートサービス経由である。全ソース検索では `MachoBindObject` 等の別の bound/moniker 入口は見つからなかった。別名のサービスに置き換える必要はない。

Host の本番組立は `dotnet/src/Eve.Host/Rpc/CoreRpc.cs` で `FacWarMgrService` を生成し、`IService.Name == "facWarMgr"` とメソッド許可リストを Macho レジストリに渡す。許可リストは下表のリモートメソッドを登録し、wrapper にだけ存在する `RefreshCorps` と `GetStats_CorpPilots` は除外する。`GetSolarSystemLPsEx` と `GetCharacterRankOverview` は登録済みだが現在の client wire caller はない。wire テストはサーバーを起動し、`CallWithKwargs` で登録した service を Host dispatcher 経由で呼ぶ。

クライアント呼び出しは positional 引数で、`machoVersion` は `CallWithKwargs` の transport kwargs であり RPC 引数ではない。メソッド固有の keyword 引数は見つからなかった。ID は `PyInt` と `PyLong` のどちらも受け、`None` は 0 として扱う。Host wire テストはこれらに加え、machoVersion 付きの呼び出しも確認する。

## Wire の状態・通知・EveJS 比較

- Corp/alliance join/leave/withdraw は `FwService` と `FwStore` の transaction に保存され、effective time に基づいて状態を読み進める。stats RPC の shapes は実装済みだが、activity totals は `RecordActivityAsync` / `AddVictoryPointsAsync` に実際に届いた daily rows のみを含む。combat producer の接続がない期間はその集計値が空/0になり得る。Character enlistment は Character store の direct faction/cooldown を更新する。Standings は `standing` relation store、stats は FwStore daily rows、donation は loyalty ledger と system LP pool を更新する。成功した mutate RPC はいずれも PyNone を返す。
- Host が送る通知は character enlistment 成功時の session change だけ。wire test で session change が RPC response より先に届くことを確認した。Corp/alliance の `OnJoinMilitia`、rank-change event と donation UI animation はクライアント側で起きる。
- EveJS 261018.1 の `server/src/services/faction/facWarMgrService.js:158-210` は4 rank handlers のみで、rank info は4-field KeyVal、overview は KeyVal list。Host はこの rank wire shape を揃える。EveJS の overview helper は保存された複数 faction 候補を出すことがあるが、現在の実装は effective enlisted faction だけを返す。EVE University [Ranks](https://wiki.eveuniversity.org/Ranks) の enlisted pilot と militia-corporation standing に基づく rank mechanics に合わせた差分。
- EveJS にない他 RPC は eve.rs の FwStore/Host state owner を使う。EveJS の未実装を成功応答の根拠にはしない。
