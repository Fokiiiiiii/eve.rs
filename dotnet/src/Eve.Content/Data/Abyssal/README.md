## Current new-run reward authority

Published reward classification and quality weights are the real builder output; the two extraction structure types are correctly unpublished SDE types49661/49662. Runtime never invents replacement item IDs.

- Main quantity policy is `retail_final`: the builder already supplies its tier curve and the runtime applies no second tier/hull multiplier.

- `RoomPlan.Loot` is empty for new plans. Each `AbyssalArtifactPlan` exclusively owns its own loot, quantity policy and source authority. No main manifest is copied into a side node.
- Main types are47951 solo /49689 co-op. `EnvironmentalObjects` are converted once from catalog definitions into Domain primitives and retained in the saved plan.

Side structure type FNV selection uses the already reserved `traceItemId` as its stable numeric planning identity. This is an intentional deterministic adapter to the source's injected dependency ports.
- Side loot uses independently injected seed `abyssal-extraction-loot-v1:{runId}:room-{room}:node-1`; blueprint copies use `abyssal-blueprint-copies:{runId}:{room}:{typeId}`. The real JS resolvers/materializer were invoked with those same dependencies for reference vectors. This makes the source's random selections immutable at planning time rather than rerolling after restart.
- Blueprint materialization remains copies with0 ME/TE and uniformly sampled runs1..5 per copy, saved in the plan.

`Procedural_main_and_side_match_executed_EveJS_vectors_for_every_profile_and_mode` compares all630 room outputs, including BPC runs, emptiness, node type, geometry, policies, stable retry and absence of duplicate ownership. The old observed mode-origin uncertainty is not used to fabricate a procedural multiplier.
