# Main CI build regression: Omega training history

## Verified findings

- Run `43674015373` failed on commit `467fdde6f` because `CharacterComposition` calls `OmegaLicenses.TrainingHistory`, while `OmegaLicenses` in that merge did not define it.
- `b83c69b61` added the `OmegaTrainingHistory` callback in `CharacterComposition` and historical training projection. `25488d9d3` later added `IOmegaAccountStore.GetOmegaTrainingHistory` and `OmegaLicenses.TrainingHistory`; that follow-up was not an ancestor of `467fdde6f`.
- V24.01 client `eve/client/script/ui/services/skillQueueSvc.py:75-79,116-129` reads the server queue and uses the returned training timestamps. `eve/client/script/ui/login/charSelection/characterSlots.py:501-529` uses the current skill's training start/end times to render progress and remaining time.
- `SkillTrainingProjectionHostTests.Registered_omega_purchase_does_not_retroactively_double_alpha_skill_training` checks that an Omega purchase does not retroactively change the Alpha-rate interval, and checks persisted history and queue projection across restart.
- EveJS v0.12.9 `server/src/services/newEdenStore/storeState.js:708-712` reads the persisted Omega training history; `server/src/services/skills/training/skillTrainingMath.js:126-128` applies the Alpha/Omega multiplier at a historical FILETIME, and `skillQueueRuntime.js:582-619` uses rate changes to calculate each queued line's timestamps. `server/src/services/skills/skillMgrService.js:524-527` returns that queue snapshot to the client. This confirms the history accessor is part of intended behavior, not an obsolete member.

## Fix

Restore the missing account history provider with a legacy fallback to the stored expiry, plus the `OmegaLicenses` accessor consumed by `CharacterComposition`. No client RPC or wire shape changed.
