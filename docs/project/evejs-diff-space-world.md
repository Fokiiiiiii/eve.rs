## ライブ比較と decoder

`tools/dev/run-evejs-live.sh /home/user/evejs-261108.1 .cache/sde/eve-online-static-data-3396210-jsonl` で EveJS は起動し、headless client の login、character 作成、選択まで応答した。通常の `SelectCharacterID(..., skipTutorial=False)` では NPE nodegraph が船に搭乗させて system へ移すため、station hangar の `GetInventory(10004).List()` は空になった。初回MITM traceのevents 101–104と server log `/tmp/cx6-evejs-logs/evejs-server.out` で確認したが、後続のproxy起動でtrace path `/tmp/cx6-evejs-undock.jsonl` を空に上書きし、初回wire記録は残っていない。同じ `tests/test_undock.py` walk を `EVE_LIVE_SKIP_TUTORIAL=1`（test helper `tools/headless-client/tests/test_undock.py:427-428`）で実行すると、EveJS は station start から全2 raceの undock / movement / dock を完了した。test result は1 passed、2 failedで、EveJS runtime の `AddBalls2` に ship と2個のstatic ball (`8500301000320001`, `8500301000320002`) があり、recorded scenario では追加entryが空という差だった。Eve.rs は同じwalk、同じ skipTutorial 条件、PostgreSQL `eve_p6` で3 passed、0 skippedとなった。eve.rs のMITM capture [`captures/cx6-eve-rs-undock.jsonl`](../../captures/cx6-eve-rs-undock.jsonl) は542 records、36 client calls、64 notifications、18 Destiny updatesを含む。EveJSの同条件 proxy capture は2回目の起動でnode processが201 tablesのpreload中にmemory cgroup OOMで強制終了され取得できず、kernel logはPID 26173を記録した（RSS 5,055,604 KB）。成功したEveJS walk自体もproxyを通していない。そのためこのwalkの直接EveJS/eve.rs JSONL diffは未実施であり、golden比較のEveJS側AddBalls2差をruntime間の差とみなさない。client は `DoDestinyUpdate` をballparkの `FlushState` に渡し (`/home/user/eve-logic/eve/client/script/remote/michelle.py:482-511`)、`AddBalls2` のstateを読み込む (`/home/user/eve-logic/eve/client/script/remote/michelle.py:1256-1272`)。追加ballの画面上の差はあり得るが、client break は確認していない。最初の空hangarはskipTutorial指定で回避できたので、EveJSが起動できないという意味ではない。

MITM は現在、marshal action と Destiny wire buffer の両方を保持する。`SetState` (packet type 0) と `AddBalls2` (type 1) の header/stamp と、連結された free/rigid ball の ID、mode、radius、position、flags、velocity、mode tail 等を field view に展開する。rigid collision tail は型依存なので推測せず raw hex で残す。未対応・切断データは offset 付き `decodeError` として記録し、元 buffer も保持する。`GotoDirection` / `WarpTo` は action 引数を tuple の要素ごとに比較する。これは比較を助ける decoder 追加であり、Destiny 全形式の native client decoder ではない。
