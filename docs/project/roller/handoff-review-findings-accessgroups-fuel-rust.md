# Review findings: access groups, structure modules, undock, and training

## Confirmed changes

### Access group summaries
A summary lookup returned private group metadata for any known ID. `AccessGroupStore.GroupSummaryAsync` now returns a summary only when the reader's effective role is Member, Manager, or Admin. `GetGroup` maps a missing summary to None, and `GetGroupsMany` omits unreadable and unknown IDs. Tests cover a private nonmember, an Everyone member, and an unknown ID at the service and Host RPC layers.

V24 calls `GetGroup` and `GetGroupsMany` from `eve/client/script/ui/services/accessGroupsController.py:172-202`; `groupInfoWnd.py:22-45` displays the returned name, description, and admins. The link implementation `ownergroups/client/link.py:14-27,37-50` carries only `accessGroup:<id>`; the V24 call path provides no publish state the server can use to distinguish a published private link from a guessed ID. EVE University says published links show the list name, description, and admins ([Access Lists](https://wiki.eveuniversity.org/Access_Lists)). eve.rs follows EveJS 261028.1's membership-filtered `GetGroup` and `GetGroupsMany` lookups (`ownerGroupManagerService.js:190-198,237-249`, `bookmarkRuntimeState.js:850-866`, `bookmarkRuntimeAccess.js:251-268`). An Everyone/member entry makes the summary readable; a private list's link does not reveal metadata to a nonmember. The private-published-link limitation is recorded in `docs/reference/compat/DEVIATIONS.md`.

### Character settlement notification order
`CharacterTraining.SettleAtFileTimeAsync` now raises `Settled` while holding the per-character semaphore, before releasing it. Its concurrency regression checks the semaphore is still held when the event fires, then verifies a single settlement and history record. This prevents a later settlement from committing and announcing before the earlier update. Raising inside the gate exposed a reentrant settle: the completed-level callback synchronizes dogma, which loads the selected ship and normally settles training again. The completion path now marks training already settled and uses `CharacterShips.LoadAfterTrainingSettledAsync`; other dogma callers still use the normal settling load. The in-space dogma refresh regression passes. V24 queue consumers replace their projected queue and scatter `OnSkillQueueChanged` in `eve/client/script/ui/services/skillQueueSvc.py:761-765`; the panel's expiry path uses that queue notification after refreshing attributes (`skillsvc.py:934-939`).

### Accelerator-expiry queue count
The restart-and-retry Host regression now asserts one queue line when the second training level completes across the booster expiry and two lines when it does not, both before and after restart. V24 refreshes attributes after `OnServerBoostersChanged` (`skillsvc.py:934-939`), rebuilds the local timing cache and redraws the in-memory queue (`skillQueuePanelNew.py:922-927,952-960`, `skillQueueSvc.py:453-459,668-678`), then consumes the projected queue from `OnNewSkillQueueSaved` (`skillQueueSvc.py:761-765`). The prior handoff citations were corrected.

## Reviewed and rejected findings

### Structure service module ownership
The candidate is a false positive. eve.rs uses one module-ownership check for online and offline; offlining then requires the module's corporation owner and Station Manager. EveJS uses a shared `moduleOwnedForHost` check and applies the same offline restrictions (`server/src/space/destiny/moduleOperation.js:2498-2677,334-357`). V24's online/offline dogma calls are in `eve/client/script/dogma/clientDogmaLocation.py:697-720`; structure unfit checks require Station Manager and a module owned by the current corporation (`eve/client/script/ui/shared/fittingScreen/structureFittingController.py:27,42`, `structureControl.py:105`). No code change is needed.

### Own-ship undock agility and max speed
The missing separate ego `SetBallAgility` / `SetMaxSpeed` actions are not a client-visible regression. V24's `Park.SetState` reads the complete ego state buffer (`eve/client/script/remote/michelle.py:967-1005`); EveJS's undock prime sends mass, optional velocity, and heading without separate agility or max-speed actions (`server/src/space/destiny/presentation/shipPrime.js:69-123`). eve.rs's recorded-reference test checks the ego max-velocity and agility fields in `SetState` (`crates/eve-space/tests/scene_matches_reference.rs:117-118`, `crates/eve-space/src/scene/tests.rs:347-365`), and the crowd case still checks separate values for another visible ship (`crates/eve-space/src/scene/tests.rs:337-365`). The headless comparator still requires action names/order and stamp groups, permits at most one second between stamp groups, and compares decoded per-item data (`tools/headless-client/tests/test_undock.py:160-185,225-303`).

The `max_velocity > 0` filter in the numbers loop applies to all ships in the view, but `ships_in_view` returns pilot session ships only (`crates/eve-space/src/crowd/ships.rs:153-163`). The pinned SDE query found 423 published Ship-category types and all 423 have positive `maxVelocity`; the only zero-valued Ship-category type is unpublished type 17360, “Immovable Enigma.” No normal published ship is filtered out. The headless test deliberately does not compare the opaque aggregate AddBalls2 buffer length because the reference includes customs offices and station props; decoded per-item slims/damage, IDs, and sentry counts remain checked (`tools/headless-client/tests/test_undock.py:225-303`, DEVIATIONS entry 16).
