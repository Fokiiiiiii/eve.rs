# NPC, Crimewatch, and Security Deep Fix

Checked: 2026-11-11. Scope: NPC spawn/behavior, combat and crimewatch timers, criminal/suspect flags, CONCORD response, security status, bounties, kill rights, wreck loot, and kill reports. The client reference is EVE Online V24.01 build 3396210 in `/home/user/eve-logic`; the executable behavior reference is EveJS 0.12.9 in `/home/user/evejs-261108.1`.

## Verified client and EveJS behavior

- V24.01 builds combat log entries from `OnDamageMessage` `source`, `target`, `owner`, and damage fields (`eve/client/script/ui/shared/uilog.py:317-367`). `UE_OWNERID` is owner kind 2 (`eve/client/script/environment/eveexceptions/const.py:6`); `godma.py:517-531` treats the value as owner identity, not proof of a character. The damage ledger therefore resolves an attacker from a live pilot first and does not turn an unrecognized owner ID into a character ID.
- The client requests recent losses/kills through `charMgr.GetRecentShipKillsAndLosses` (`eve/client/script/ui/shared/info/infosvc.py:2648-2653`), retrieves reports through `warStatisticMgr.GetKillMail(killID, hash)` (`eve/client/script/ui/shared/killReportUtil.py:39-43`), and renders attacker/item data from `killBlob` (`eve/client/script/ui/shared/killReport.py:149-164`). `charactersheet.py:90-92` invalidates the recent-kill cache on `OnKillNotification`.
- EveJS accumulates damage by attacker identity, source ship, and weapon, then builds a kill report at destruction from the final blow, damage, ship/item outcomes, and bounty (`server/src/space/combat/killmailTracker.js:188-226, 919-1024`). It persists the record and fans out notifications after commit (`:1041-1123`; `server/src/services/killmail/killmailNotificationFanout.js:84-190`). Its owner kill-log predicate excludes NPC victims, so a rat kill does not create a player kill-log notification (`server/src/services/killmail/killmailPreparationTasks.js:207-225`). Abyssal NPC outcomes are also intentionally suppressed from public killmails (`killmailTracker.js:938-944`).
- EveJS serializes killmail item contents to one nested level (`server/src/services/killmail/killmailPreparationTasks.js:105-118, 141-154`); the eve.rs killBlob serializer follows that wire shape. The persisted event still retains the complete item outcome tree for valuation and audit.
- V24.01 autopilot waits until `surfaceDist` is within interaction range (`eve/client/script/parklife/autopilot.py:545-555`). EveJS scoop validation subtracts both ship and container radii (`server/src/services/ship/cargoContainerRuntime.js:1133-1163`, `server/src/space/destiny/projection/range.js:26-50`). Empire sentry targeting is in `eve/client/script/behaviors/monitors/combat.py:357-406`; the corresponding EveJS runtime keeps the offender as the target after a security-status loss (`server/src/space/npc/empireSecurity/empireSentryRuntime.js:38-58, 61-103`).
- The broader timer, CONCORD response, and security-loss comparisons are recorded in `docs/project/evejs-261108-port-concord-crimewatch.md`. That record cites V24 client timer states, CCP timer material, EveJS response timing, and the security-loss equation and documents the known difference between EveJS responder travel and eve.rs spawn timing.

## Changes

- Added a bounded, 30-minute damage ledger and destruction event data for player ships, capsules, profiled NPCs, and simulation-owned NPCs. It keeps pilot/corporation attribution, damage, weapon, and final-blow identity without inventing type or faction data when the simulator did not provide it (`dotnet/src/Eve.Services.Space/SpaceSessions.Killmails.cs`, `SpaceSessions.Death.cs`, `SpaceSessions.Npc.cs`, `SpaceEvents.cs`). Abyssal NPC public killmails remain suppressed, matching EveJS.
- Wired the killmail event to a Host subscriber that writes the GameStore record and hash blob in the event transaction, records NPC/player bounty and kill-right outcomes, and persists victim/final-blow notifications. The after-commit path updates the cache and sends `OnKillNotification` / `OnShipDeath` in client-visible order (`dotnet/src/Eve.Host/Persistence/Killmails/PersistenceShipKillmailRecorder.cs`, `dotnet/src/Eve.Host/Composition/{Mail,LegacyGameStore,Ship,Space}Composition.cs`).
- Player bounty claims now join the killmail subscriber transaction, are idempotent per destroyed ship, and schedule fleet/pilot payout work through the durable scheduler. The claim amount is included in the report (`dotnet/src/Eve.Services.Crimewatch/PlayerBountyKills.cs`, `dotnet/src/Eve.Crimewatch/PlayerBountyStore.cs`).
- Ship death resolves inventory once and keeps the same dropped/destroyed quantities and nested contents for persistence and the report (`dotnet/src/Eve.Inventory/DeathOutcome.cs`, `dotnet/src/Eve.Ships/CharacterShips.Death.cs`).
- Wreck/can range now measures surface-to-surface distance, subtracting both the ship radius and target radius (`crates/eve-space/src/crowd/wrecks.rs`, `dotnet/src/Eve.Space/SimMessages.cs`).
- Serialized the complete Host refresh of the shared `client_sde.mission_messages` table with a PostgreSQL transaction advisory lock. Before this change, two Host tests in the selected suite failed at startup with SQLSTATE `23505` on `mission_messages_pkey`; concurrent `DELETE` statements on the empty shared table did not serialize. The lock is acquired before schema/table setup and held through the replacement transaction (`dotnet/src/Eve.Host/Composition/MissionComposition.cs`).
