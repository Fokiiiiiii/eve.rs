## Silo-cycle behavior added

`SpaceContainers` persists the next cycle deadline and schedules a keyed durable one-shot job from the tower's SDE `posControlTowerPeriod` attribute. Configuring a graph while its tower is offline does not run or queue a cycle; when the tower becomes online, the Host schedules the first cycle. Offlining/depleting the tower cancels its pending cycle. The Host rebuilds schedules from persisted configurations at startup. Each scheduled transfer, inventory mutation, cycle-state update, and next job is committed in the scheduler transaction; after commit, the Host sends `OnMoonProcessChange`.

The pinned SDE in `eve_p3` reports `dogmaAttributes` key 722 as `posControlTowerPeriod` with millisecond units. The Amarr Control Tower type 12235 has a 3,600,000 ms period. The test derives the interval from `DogmaStatic`, not a captured packet or runtime constant. EveJS uses that same type attribute when it reconciles the cycle (`starbaseProductionCycles.js:201-214`).

The registered Host/PostgreSQL test `ControlTowerHostTests::PosMgr_forced_production_cycle_moves_configured_material_between_online_silos_over_host_wire` covers the first-link offline state, GM denial, offline destination, SDE-capacity-limited forced transfer, serialized concurrent/retried calls, schedule restoration, scheduler restart, automatic transfer, and persisted item custody/quantity/cycle state. The Host composition test also binds and lists a silo while it is offline, then confirms that an online-cycle transfer emits `OnMoonProcessChange` only. This matches EveJS: `validateProductionInventoryAccess` rejects online silos (`starbaseProductionRuntime.js:213-224`), and `_canSessionObserveSpaceContainerInventory` filters observers whose scope is no longer authorized (`invBrokerService.js:6485-6509`). The test's initial incorrect `OnItemChange` expectation failed; after checking these source paths, it was corrected to the verified notification behavior. The focused scheduled-cycle test passed 1 test, 0 failed, 0 skipped.
