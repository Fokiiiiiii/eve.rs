## Protocol (observed in the public EveJS code, not a CCP spec)
TCP frame = uint32 little-endian payload length + payload; marshal payload = 0x7E + uint32 map count + encoded object; MachoNet packet tuple [type, source, destination, userID, payload, namedPayload, oob?, bssid?, spanid?, ...up to 14 elements accepted since 23.02]. Message types: 0 AUTH_REQ, 1 AUTH_RSP, 2 IDENT_REQ, 3 IDENT_RSP, 6 CALL_REQ, 7 CALL_RSP, 8 TRANSPORTCLOSED, 10/11 RESOLVE_REQ/RSP, 12 NOTIFICATION, 15 ERRORRESPONSE, 16 SESSIONCHANGENOTIFICATION, 18 SESSIONINITIALSTATENOTIFICATION, 20/21 PING_REQ/RSP, 100 MOVEMENTNOTIFICATION. Handshake: server VersionExchangeServer (eveBirthday, machoVersion, user count, boot_version, boot_build, project version) -> client VersionExchangeClient -> (None,"VK",key) -> CryptoRequestPacket -> "OK CC" -> CryptoChallengePacket(login) -> PyInt(2)+CryptoServerHandshake -> CryptoHandshakeResult -> CryptoHandshakeAck + SessionInit. EveJS implements PLACEBO only; production cipher, key derivation, anti-replay are UNKNOWN. No transport-level sequence counter is visible (TCP ordered; bssid/spanid look like trace metadata). Use application-level idempotency for RPCs. Parser state machine: READ_LENGTH -> (0 < len <= MAX_FRAME, configurable) -> READ_PAYLOAD -> MARSHAL_DECODE -> MACHO_PACKET_DECODE -> SESSION_STATE_CHECK -> SERVICE/METHOD AUTHORIZATION -> DISPATCH.

## Architecture facts (CCP sources)
Load balancer -> PROXY (client sessions) -> SOL nodes (solar-system simulation and services) -> SQL; chat, search, images, gateways, message bus live outside the cluster; modern Quasar side uses NATS for async fan-out. Destiny physics runs at 1 Hz per solar-system ballpark (pre-tick: apply client actions/server events and make updates; simulate movement/collision; post-tick: attach/cleanup); no blocking DB in a tick. Hot systems (Jita) and the Forge market get dedicated nodes. 2023 figures (about 170 solar nodes, 40 character-service nodes) are historic, not 2026. Proposal: single-writer solar-system actor with (owner_node, revision) per entity; cross-system jump as idempotent PREPARE/reserve/COMMIT/activate with a transfer_id; wallet/market in DB transactions; chat/image/telemetry eventually consistent.

## Persistence (EveJS today; proposals for eve.rs)
EveJS: in-memory cache, 2,000 ms debounce flush, SQLite tables of (key TEXT PRIMARY KEY, json TEXT), WAL, synchronous=NORMAL, foreign_keys, busy_timeout 5000. Proposal: normalised tables (account, character, session, inventory_item, ship_module, skill/skill_queue, wallet, wallet_journal with idempotency_key unique, market_order with version, solar_system_state, entity with monotonic revision, domain_event); ISK as fixed-point; transfer invariant sum of balance deltas = 0 in one transaction; SDE kept separate from runtime data, import via version-specific importer, retain retired types as tombstones or per-release keys.

## Game-logic formulas visible in the public EveJS (not CCP-published; match against observation)
Turret: omega = v_tangential / d_center; T = omega*S_weapon / (V_tracking*S_target); R = 0 if d <= optimal else (d - optimal)/falloff; P_hit = 0.5^(T^2 + R^2); roll r > P_hit misses; r < 0.01 is a wrecking hit with quality 3.0; a normal hit has quality 0.49 + r. Missile: range ~ v_max * t_flight; S = sig_target / radius_explosion; V = S * v_explosion / v_target; application = min(1, S, V^e) with e from the damage-reduction parameter. June-16 rule: simulation-mission capacitor recharge TIME x0.5 (change the time constant, not the amount). Suggested golden vectors: optimal range edge, falloff edge, zero angular velocity, wrecking threshold 0.009999/0.010000, stationary missile target, signature = explosion radius, wallet retry with the same idempotency key, market race, jump handoff crash, mission relog, ruleset June16 vs June19.

CCP: physics 1 tick/s; Tranquility average about 0.7 operations per session per second; Quasar test 500 users about 45,000 messages/s; a Tranquility-wide example about 30,000 messages/s. Load scenarios: handshake storm, 24-48 h soak, movement-heavy, dense single grid, weapon activation burst, market hotspot, jump storm, mission wave burst, forced node restart, SDE cold boot, malformed-protocol fuzz. ## Security
2026-09-08 CCP security update: a modified client used donation operations so a recipient's wallet balance was returned; about 1,000,000 zero-ISK donations from 4 accounts in about 6 hours exposed character/corporation master wallet balances (not usernames/emails/PLEX/transaction history). Root cause: an API returning fields the caller should not see. Regression tests to add: donate(0 ISK, victim) must not reveal the victim's balance; getInfo(otherCharacter) object-level authorisation; market buy with the same request id twice; contract accept concurrently twice; jump the same ship through two session paths; CALL_REQ before SessionInit; CALL_REQ to an admin-only service; oversized marshal string/list; deeply nested substream; partial and coalesced TCP frames. Dispatch precondition: syntax valid AND authenticated AND correct session state AND authorised service AND authorised method AND typed/range-valid args AND authorised target object AND idempotency satisfied. Passwords with a memory-hard KDF, MFA for admin accounts; response projection before serialisation; session ids from a CSPRNG with expiry/rotation; per-account/IP login throttling; internal channels authenticated. EveJS PLACEBO handshake is for compatibility testing, not internet-facing authentication. Do not confuse CCP SSO/ESI OAuth (JWT verification against JWKS) with the MachoNet game login.
