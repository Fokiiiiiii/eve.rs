# Crimewatch, security status, and insurance deep fix

## Finding and correction

A low-sec attack on an unflagged ship is an unlawful suspect offense. The server recorded the suspect flag but skipped the security-status loss because the penalty listener accepted only criminal outcomes. EVE University says an unprovoked ship attack in low or high security space reduces security status, using the ship modifier and system-security adjustment ([Security status](https://wiki.eveuniversity.org/Outlaw)). The V24.01 timer consumer treats state 304 from `OnCriminalTimerUpdate` as the suspect timer (`eve/client/script/ui/crimewatch/crimewatchTimers.py:405-424`); system flag changes arrive separately through `OnSystemCriminalFlagUpdates` (`crimewatchSvc.py:246-254`).

The Host flow is `SpaceSessions` aggression callback → `CrimewatchRuntime.RecordAggressionAsync` → persisted crimewatch state → `Aggressed` consequences → timer and flag notifications (`dotnet/src/Eve.Host/Composition/SpaceComposition.cs:302-305`, `dotnet/src/Eve.Services.Crimewatch/CrimewatchRuntime.cs:194-246`). `Aggression.Record` labels a low-sec ship offense `Suspect` and a low-sec capsule offense `Criminal` (`dotnet/src/Eve.Crimewatch/Aggression.cs:59-76`). The client reads its five timer states on location changes (`eve/client/script/ui/services/crimewatchSvc.py:95-108)); its security-status cache is read at lines 589-603 and refreshed by `OnSecurityStatusUpdate` at 597-599. Ship attribute changes pass through `godma.py:360-365` and `clientDogmaLocation.py:309-341`; the security-tag window refreshes on the status notification (`securityOfficeWindow.py:145-147`). The headless walk describes the attack, status, and notification sequence (`tools/headless-client/tests/test_aggression.py:1-7`).

EveJS 261028.1 calls `applySecurityStatusPenaltyForAggression` from high-sec criminal-offense handling (`server/src/services/security/crimewatchState.js:2315-2496,3477,3539`); its callsites do not attach that penalty to a low-sec ship-suspect outcome. The wiki mechanics take priority. eve.rs now applies the existing formula to illegal attack outcomes marked suspect or criminal, retaining the existing floor, duplicate-target window, transaction history, and notification order (`dotnet/src/Eve.Services.Crimewatch/SecurityStatusPenalties.cs:49-111`, `dotnet/src/Eve.Crimewatch/SecurityPenalty.cs:10-34`). Host writes the status relation and history in a database transaction (`dotnet/src/Eve.Host/Composition/SpaceComposition.cs:462-490`).

The `Aggressed` event also carries remote-assistance results. EveJS's penalty is specific to attacks, so `AggressionResult` now identifies the action; attacks default to `Attack`, while `RecordRemoteAssistanceAsync` marks its result explicitly (`dotnet/src/Eve.Services.Crimewatch/AggressionResult.cs:8-11`, `CrimewatchRuntime.cs:230,286-306`). The penalty listener ignores remote assistance even when it causes a criminal flag.

## Insurance flow reviewed

The V24.01 insurance window lists personal contracts and, for accountant or junior-accountant roles, corporate contracts (`eve/client/script/ui/station/insurance/base_insurance.py:96-121`). It requests quotes for eligible singleton ships, prompts for terms, calls `InsureShip`, and retries with `voidOld=True` only after `InsureShipFailedSingleContract` (`base_insurance.py:162-216,519-552`). The server returns that error with the expected owner field, maps insufficient funds to `NotEnoughMoney`, and sends `OnShipInsured` after an applied purchase (`dotnet/src/Eve.Services.Core/InsuranceService.cs:438-477,543-557`). The client handles `OnShipInsured` in the insurance service and ship overview (`base_insurance.py:217-219`, `eve/client/script/ui/shared/info/shipInfoPanels/panelOverview.py:35-38,315-317`).

On ship loss, Host skips capsule losses and calls the insurance settlement writer with loss cause and owner (`dotnet/src/Eve.Host/Composition/SpaceComposition.cs:343-353`); the PostgreSQL writer checks the ship and active contract and uses the loss payout ledger before crediting the wallet (`dotnet/src/Eve.Host/Persistence/Insurance/PersistenceInsuranceWriteModel.cs:186-225`). The wiki describes the 40% baseline, 50–100% contract tiers, 12-week term, and no payout for CONCORD losses ([Ship Insurance](https://wiki.eveuniversity.org/Ship_Insurance)). EveJS also detects CONCORD losses (`insuranceRuntime.js:1251-1265`) and finalizes payout through its loss ledger before notifying the owner (`insuranceRuntime.js:860-898`). No insurance defect was identified in these purchase, notification, and loss-settlement paths during this pass.

## Regression evidence

Added PostgreSQL-backed crimewatch wire tests for the suspect ship attack and remote-assistance boundary (`dotnet/tests/Eve.Services.Crimewatch.Tests/RuntimeTests.cs:1375-1410`). Before the fix, the low-sec case failed because the security-status write list was empty; after the fix, the full `PenaltyTests` filter passed 8/8 and `RuntimeTests` passed 29/29, with no skipped tests. The test checks the −0.075 status change at 0.3 system security, notification order, suspect timer state 304, and the system's suspect set.

The local regression uses the real PostgreSQL crimewatch store and captures V24-shaped notifications, but it does not exercise the graphical client. The broad insurance test suite and live headless walk were not exercised.
