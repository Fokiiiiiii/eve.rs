# GameStore audit fixes (2026-11-09)

This records the verified findings from `/home/user/reports/90-audit-gamestore-r15.md`. The seven numbered findings were reproduced and fixed. The report's opening statement that the current Host has no GameStore runtime dependency is stale: `GameStoreReaders.ReadGameStoreTableAsync` reads through `GameStoreCache` (`dotnet/src/Eve.Host/Composition/GameStoreReaders.cs`), and Host composition still wires the legacy mail store (`dotnet/src/Eve.Host/Composition/LegacyGameStoreComposition.cs`). This scope correction does not change the seven findings.

## Findings and changes

1. **High — enqueue commit acknowledgement loss.** The old cache only retained an outbox operation after `EnqueueAsync` returned. A PostgreSQL commit followed by a lost acknowledgement left an untracked durable operation, so the next enqueue hit the per-table pending constraint. `FlushTableCoreAsync` now looks up the pending operation for the active owner and table, reconciles its recorded batch, advances the baseline, and then derives the next diff. `A_retry_reconciles_an_enqueue_whose_commit_acknowledgment_was_lost` injects the lost acknowledgement after commit; before the fix the retry failed with `PERSISTENCE_OPERATION_PENDING`, and after the fix it reconciles and clears the outbox without restarting.

2. **High — shutdown during an in-flight flush.** Each table now exposes an internal completion task for the active flush. Disposal waits for active flushes and repeatedly drains dirty rows and pending operations until none remain. `Dispose_waits_for_an_in_flight_flush_and_drains_changes_written_during_it` holds the database apply transaction, writes a second row, begins disposal, then verifies disposal waits and both rows survive.

3. **Medium — `ForceExclusive` from non-maintenance roles.** `AcquireOwnerAsync` now rejects that option before opening a transaction unless the normalized role is `maintenance`. `Force_exclusive_is_rejected_for_non_maintenance_roles_without_revoking_maintenance` verifies the refusal code and that the existing maintenance fence remains active.

4. **Medium — clearing a transient marker.** Clearing markers now marks every affected row dirty and schedules a flush. `Clearing_a_transient_marker_persists_its_value_without_another_write` changes the value while transient, clears only the marker, flushes, and reloads a second cache to verify the changed value was persisted.

5. **Medium — transient array entries.** The snapshot filter now writes JSON `null` at a transient array index, preserving the remaining indices and preventing the filtered value from reaching PostgreSQL. `A_transient_array_element_is_excluded_as_a_json_null_in_the_flush_snapshot` checks the live cache still holds the secret while the database snapshot contains a null at the same array slot.

6. **Medium — forced transient writes.** The flush snapshot now restores the forced path after applying transient filters. Versioned markers are cleared only when that batch is acknowledged, so a newer concurrent force remains pending. `A_forced_transient_write_is_included_in_its_flush_batch` checks the value reaches PostgreSQL while its transient marker remains set. An additional same-value force regression covers the `Force` contract when the in-memory value already matches.

7. **Low — migration table-name validation.** `MarkMigratedAsync` now uses the same `RequirePersistence` validation as other persistence mutations. `Migration_markers_reject_internal_and_sqlite_tables` checks internal metadata tables and `sqlite_master` are rejected.

No numbered finding was false. No assertion was weakened and no test was skipped to make a result pass.
