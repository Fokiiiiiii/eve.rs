# Wormholes, null-sec, faction warfare, and incursions: deep correctness handoff

Date: 2026-11-01

## Scope and result

The core wormhole jump flow had a concurrency defect: two pilots could both be accepted by the simulation while the same connection still showed enough mass, before either accepted jump committed its mass debit. The fix serializes a connection's jump interval in one Host process, reloads endpoint and mass after acquiring the gate, then keeps the gate through simulation acceptance, durable transit, collapse publication, polarization, and destination placement.

The targeted database regression was observed failing before the gate was restored: it found two `SimCommands.Jump` commands for a connection with only one ship's mass. With the fix restored, the test asserts exactly one command, one successful pilot, one refused pilot, and the remaining connection end. This gate is process-local; multi-Host deployments need a database reservation before simulation acceptance.

## Wormhole client contract and path

- The only V24.01 jump caller found in the whole `/home/user/eve-logic` tree is `eve/client/script/ui/services/menuSvcExtras/movementFunctions.py:592-598`. It optionally confirms entry from high security space, then calls `sessionMgr.PerformSessionChange(... wormholeMgr.WormholeJump, itemID)`; the RPC has one positional end ID and is a session transition.
- The other wormhole manager caller is `spacecomponents/client/components/jumpPolarization.py:23-37`. On a wormhole component update it calls `GetWormholePolarization(itemID)`; `None` clears polarization, while a pair supplies end time and duration, broadcasts the update, then sleeps until expiry. No other client callsites for these RPCs were found by whole-tree search.
- The visual consumer is `eve/client/script/environment/spaceObject/wormhole.py:16-33`, which reads `nebulaType`, `wormholeSize`, `wormholeAge`, and `maxShipJumpMass` from the slim item. The refusal consumer `eve/client/script/parklife/spaceMgr.py:93-97` handles `OnWormholeJumpCancel` by clearing indications and displaying `UI/Wormholes/EnterCollapsed`.
- Host wiring is `dotnet/src/Eve.Host/Rpc/SpaceRpc.cs` constructing the manager service and `dotnet/src/Eve.Services.Space/ActivityTravelRpcServices.cs:176-229` adapting the jump tuple to the client list shape and polarization to `[FILETIME, seconds]`. `SpaceWormholes.cs:122-205` checks pilot, movement policy, current endpoint, same-direction polarization, ship mass, and available connection mass; it returns a collapsed/unknown endpoint as `STARGATE_NOT_FOUND`, a too-heavy ship as `CustomNotify`, and polarization as `CustomNotify`. On accepted simulation jump, the host debits the durable connection, publishes any collapse change, stores five-minute pilot/end polarization, places the destination end, and returns the session-transition tuple. The subsequent simulation jump event performs the session change.
- The root ordering hazard is between simulation acceptance and database debit: `dotnet/src/Eve.Wormholes/WormholeWorld.cs:101-118` delegates the debit transaction to `WormholeJobs.TransitAsync`; `dotnet/src/Eve.Wormholes/WormholeJobs.cs:67+` locks and updates the stored connection, but that transaction alone cannot prevent a second simulation command from being accepted first. The per-connection gate now covers that interval in `SpaceWormholes.cs:139-205`.
- EveJS 261028.1 uses `/home/user/evejs-261028.1/src/server/src/services/exploration/wormholes/wormholeMgrService.js:207-318` and `wormholeRuntime.js:990-1007,2075-2157`; it reserves a prepared jump before effects and the delayed transition. Its reservation supports runtime serialization; eve.rs retains PostgreSQL as the durable mass authority and adds the smallest Host gate around the accepted-simulation/debit interval.
- EVE University [Wormholes](https://wiki.eveuniversity.org/Wormholes) describes five-minute per-pilot same-direction polarization and per-transit / total mass limits. The five-minute duration and mass decisions remain rule/SDE-derived; this change addresses concurrent use of those limits rather than changing their values.
