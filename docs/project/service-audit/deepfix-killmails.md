# Insurance payout notification correction (CX5)

## Scope and finding

Audited the player-facing insurance flow: quote and contract display, purchase/replacement, cancellation, ship-loss settlement, wallet credit, notification delivery, and settlement retry. Whole-client search found one InsuranceSvc implementation in `eve/client/script/ui/station/insurance/base_insurance.py:35-42`; UI callers are `:390-401` (cancellation) and `:532-542` (purchase, replacement retry and error handling). The replacement retry is only offered after `InsureShipFailedSingleContract` (`:535-541`). `OnShipInsured` only highlights the UI icon (`:217-218`); the overview panel listens and refreshes that icon (`eve/client/script/ui/shared/info/shipInfoPanels/panelOverview.py:36-37,315-316`).

Found a missing client-visible transition: successful Host loss settlement credited the wallet and persisted the insurance settlement, but never created notification type 35. The client registers type 35 as Insurance Payment and group 11 as Insurance (`eve/common/script/util/notificationconst.py:38,654,732-735`), then formats the notification with `data['payout']`; true selects the default-payout text (`eve/common/script/util/notificationUtil.py:202-206,1177-1178`). A full-client search for `InsurancePayout`, `notificationTypeInsurancePayoutMsg`, and `groupInsurance` found the constants, formatter, and notification texture mapping (`notifications/client/controls/notificationTextures.py:38-40`); no other insurance payout consumer or caller was found.

## Behavior cross-check

EveJS 261028.1 calls `notifyInsurancePayout` after successful payout finalization (`server/src/services/insurance/insuranceRuntime.js:859-898`). The notification writes sender 1000113 and insurance group, and data `{itemID, amount, payout}` (`server/src/services/insurance/insuranceNotifications.js:13,25-40,59-77`). Its `payout` flag is true for default payout and false for insured-contract payout (`insuranceRuntime.js:886-898`).

The Host now writes the same type/group/sender and data through the existing persistent notification adapter, with a per-loss idempotency key (`dotnet/src/Eve.Host/Persistence/Mail/PersistenceMailSendHostAdapter.cs:409-416`). Settlement sends the notification after committing the authoritative payout and wallet event, saves the recipient and payout kind for retry, and replays the idempotent notification on an already-applied settlement (`dotnet/src/Eve.Host/Persistence/Insurance/PersistenceInsuranceWriteModel.cs:204-220,239-278,296-300`). CharacterComposition supplies the existing mail/notification writer (`dotnet/src/Eve.Host/Composition/CharacterComposition.cs:210-212`).

A no-contract loss is the default-payout case: EveJS sets `isDefaultPayout` when the operation has no contract (`insuranceRuntime.js:886-898`); the Host also marks a contract invalid at loss time or a CONCORD loss as default (`PersistenceInsuranceWriteModel.cs:239-240`). This flag is what the client formatter consumes. EVE University describes the default 40% reimbursement, 12-week policy validity, payouts for ship losses except losses to CONCORD, and default coverage after policy-ending actions such as repackaging or transfer ([Ship Insurance](https://wiki.eveuniversity.org/Ship_Insurance), “Core mechanics” and “Reimbursement calculation”). These rules support distinguishing insured payout from default payout; the implemented payout amounts continue to come from the existing SDE-backed quote mechanics. The insurance notification recipient follows the final character owner when present, matching the EveJS payout's recipient character; Host settlement requests provide that owner from the ship-loss path.

## Regression proof and checks

Added a registered-Host PostgreSQL test in `dotnet/tests/Eve.Host.Tests/InsuranceRpcHostWireTests.cs:107-108,237-249,253-268`. It checks the notification wire row, sender, ship ID, amount, insured/default flag, retry deduplication, and wallet totals. The notification RPC intentionally returns its seven reference fields and omits `groupID` (covered by `NotificationMgrServiceTests.Backed_rows_have_exact_reference_fields_types_and_descending_ids`); group 11 is supplied to the persistence adapter as client notification metadata. Before the implementation change the focused test failed because no type-35 payout notification existed. Afterward the Host.Tests build passed; database-backed Host insurance/notification tests passed 4/4 with 0 skipped on `eve_p5`; InsuranceServiceTests passed 34/34 with 0 skipped.

## Scope boundary

This change addresses the insurance payout path. Bounties, kill rights, killmails, loot and non-insurance payout behavior were not deeply re-audited in this pass. The purchase/cancel wire flow had prior evidence in `docs/project/insurance-market-rpc-handoff.md` and `docs/project/service-audit/DEEPCHECK_insurance.md`; this change adds the previously missing loss-settlement notification.
